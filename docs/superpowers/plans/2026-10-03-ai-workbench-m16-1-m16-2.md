# M16.1–M16.2 模型端点能力与连接自检实施计划

> **For agentic workers:** Use `superpowers:executing-plans` to执行本计划；当前会话禁止使用子代理，只能在主会话内按任务推进。

**Goal:** 只交付 M16.1 和 M16.2：统一模型端点能力契约，并提供用户主动触发的连接自检与能力缓存。

**Architecture:** 端点归一化、探测结果分类和诊断脱敏放在基座纯函数层；AI 总结插件负责实际网络探测、取消、缓存和设置页 UI；AI 工作台只读取脱敏的 provider 状态，不直接处理 API Key 或原始错误。

**Tech Stack:** Userscript、ESM、esbuild、Node `node:test`、jsdom、Edge/Chromium CDP fixture。

## Global Constraints

- 本轮只做 M16.1、M16.2；M16.3 诊断历史 UI、M17 导出/导入均暂缓。
- 不改变 M12–M15 已验收的流式回答、停止/重试、材料范围、引用复核和站内写操作链。
- 自检只在用户点击后运行，使用固定最小请求；不发送当前页面、对话历史、引用、研究候选或站内写操作字段。
- 诊断结果只保留协议、能力、状态分类和延迟；不得保存 API Key、Authorization、Cookie、CSRF、完整查询参数、提示词或回答正文。
- 不执行 `reset`、`clean`、`commit`、`push`；保留工作区已有修改。
