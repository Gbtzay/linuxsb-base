# 双 UI 模式：旧三段式与 iOS 27 单画布设计

日期：2026-10-06
状态：设计经用户确认，等待规格审阅。
范围：`plugins/skin.user.js`、`src/shell-boot.js`、相关测试与浏览器烟测。

## 目标

让使用者可以在旧版固定三段式 UI 和当前 iOS 27 单画布 UI 之间选择。缺少模式设置时默认旧三段式；这一规则同样适用于已经安装的使用者。旧三段式在适合并排显示栏目的宽屏上显示左侧导航、中间正文、右侧信息栏；窄屏使用站点原生响应式布局。iOS 27 单画布继续保留现有行为与外观设置。

## 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 可选模式 | 旧三段式、iOS 27 单画布 |
| 首次与缺失设置的默认模式 | 旧三段式；现有安装也切回旧三段式 |
| 旧模式布局 | 固定左导航 / 中间正文 / 右信息栏，不是可拖动窗口模式 |
| 模式设置范围 | 全站生效，保存于皮肤插件配置 |
| 设置位置 | 皮肤插件的“界面精修”设置表单中的“界面模式”选择器 |
| 旧模式窄屏行为 | 退回站点原生响应式布局，避免三栏挤压内容 |
| 皮肤总开关 | 继续由现有 `shell` 开关负责；模式选择不取代它 |
| 模式切换 | 保存选择后立即切换，不刷新页面；保留当前路由、原生内容节点和滚动位置 |
| iOS 27 外观数据 | 保留，不因切回旧模式而删除 |

## 当前实现背景

`plugins/skin.user.js` 仍包含旧壳的顶栏、左导航栏、右信息栏和固定布局 CSS，同时也包含 `#lsb-shell` 的 iOS 27 画布结构。画布状态和外观数据另存于 `canvas-state:v2`。当前启动逻辑为所有已启用的皮肤添加 `lsb-canvas-mode`，并由 `refreshShell()` 始终挂载画布，所以保留的旧壳渲染路径无法被正常选择。

旧壳还包含可拖动窗口模式。该模式与用户确认的旧固定三段式不同；新增双模式设置后，旧模式必须固定使用三段式布局，不得因历史 `layoutMode` 值进入可拖动窗口模式。iOS 27 模式继续使用现有画布实现，不重建页面内容，也不改变 AI、路由、网络或写操作流程。

## 设计方案

### 模式配置

在皮肤插件 manifest 中增加 `uiMode` 选择器，值为 `legacy` 或 `ios27`，显示名称分别为“旧三段式”和“iOS 27 单画布”。旧模式是 manifest 默认值。运行时采用白名单归一化：只有明确的 `ios27` 才进入单画布模式；字段缺失、空值或未知值均按 `legacy` 处理。这样已安装用户没有 `uiMode` 值时也会进入旧模式。

现有 `shell` 开关保持独立。关闭 `shell` 时两种氢壳 UI 均不挂载，原生页面恢复。模式字段由现有插件配置存储并在保存配置后触发重新挂载；“立即切换”指无需整页刷新，而不是更改下拉框时绕过设置页的保存动作。

### 模式路由

增加单一的有效模式判断，使所有入口——初始挂载、设置变更、路由更新、重新启用——遵循相同规则：

- `uiMode === 'ios27'`：运行现有 `mountCanvas()`，保留 `lsb-canvas-mode`、iOS 27 Surface、媒体与外观逻辑。
- 其他有效输入均归一为 `legacy`：宽屏运行现有 `ensureShell()` / `fillShell()` 旧壳路径，禁止挂载画布 Surface，也不启用拖动窗口模式。
- 旧模式在窄屏不创建固定栏壳，恢复站点顶栏、侧栏和正文的原生响应式显示。完整三段式的最小宽度使用现有三栏样式断点 `1100px`；`1100px` 及以上显示完整三栏，低于该宽度回到原生布局。
- 更新 `applyMarkers()`，使 `lsb-canvas-mode` 只在单画布模式开启；旧模式不得继承单画布的正文宽度、顶部留白或滚动样式。
- 更新 `src/shell-boot.js`：只有显式选择 `ios27` 时才创建 iOS 27 首屏占位画布。旧模式让站点原生页面保持可见，直到皮肤脚本挂载旧壳，避免错误显示单画布占位层。

### 模式切换与 DOM 生命周期

模式变化时只重建展示层，不导航或替换当前页面。切换流程先读取当前滚动位置，再卸载已启用的展示层：关闭该层的事件监听、观察器、定时器和滚动桥；恢复搜索框、主题按钮、个人资料卡、右侧栏卡片以及其它由旧壳或画布临时收纳的站点节点；移除该展示层拥有的状态类和节点。之后再挂载目标 UI，并恢复原滚动位置。

每个时刻最多存在一个有效壳。正文、表单、帖子、链接和编辑器继续使用站点现有 DOM；不复制帖子或写操作控件。切换过程中保留当前 URL 与正文节点身份，不清空 `canvas-state:v2`，也不影响未涉及的插件配置。

如果目标壳挂载失败，清理未完成的表面与状态后显示原生页面；不得遗留隐藏的正文、重复导航、被移动后未归还的节点或无法滚动的页面。

### 状态与兼容性

- `uiMode` 只表达 UI 形态，不并入 `canvas-state:v2`。画布外观、媒体引用与站点覆盖状态仍独立保存。
- 旧模式始终选择旧固定三段式；旧 `layoutMode` 或旧窗口布局数据不得改变其呈现，也不得写入新的模式字段。
- iOS 27 的宽、中、窄屏行为与当前画布测试保持一致。
- 禁用皮肤、重新启用、模式切换、SPA 路由更新和插件停用都必须维持现有 DOM 恢复约束。
- 模式选择与默认规则不改变网络权限、AI 安全链、CSRF、确认流程或站内写操作语义。

## 测试与验收

### 配置与默认值

- 新安装的配置默认 `legacy`。
- 已有用户配置缺少 `uiMode` 时运行 `legacy`，即切回旧三段式。
- 明确配置 `uiMode: 'ios27'` 时运行当前单画布；未知值安全归一为 `legacy`。
- `shell: false` 时两种壳都卸载，原生 UI 恢复。

### 结构与切换

- 宽屏旧模式显示旧顶栏、导航、正文与右侧信息栏；不创建 `[data-lsb-canvas-surfaces]`，不添加 `lsb-canvas-mode`，也不产生窗口拖动 chrome。
- iOS 27 模式保留已有状态胶囊、导航、Sheet、画布布局和外观行为。
- 双向切换无需刷新，保留当前 URL、正文节点身份和滚动位置。
- 搜索、主题切换、个人资料和侧栏节点在切换后均只存在一份，且停用时回到原生父节点。
- 连续切换与路由更新后不得出现重复 shell、孤立 surface、残留样式类或未释放监听器。

### 响应式与浏览器

- 在 `1100px` 及以上检查旧三栏布局完整、内容和右栏不互相覆盖。
- 在 `1099px`、`700px` 和手机宽度检查旧模式回退站点原生布局，顶栏、侧栏、正文可用且无横向溢出。
- 对首页、版块列表、帖子、个人页和设置页运行两种模式覆盖；至少对首页与帖子页执行宽屏、断点和窄屏浏览器检查。
- 确认默认旧模式不会创建 iOS 27 document-start 画布占位；显式选择 iOS 27 时原占位与画布接管流程仍通过。
- 运行相关 Node 测试、`node scripts/check-skin-browser.mjs`、`npm run build`、`npm run verify:dist` 与 `git diff --check`。

## 非目标

- 不重写旧三段式布局、iOS 27 画布、帖子渲染、导航来源或 AI UI。
- 不向用户开放第三种可拖动窗口模式。
- 不迁移或删除当前 iOS 27 外观与布局状态。
- 不调整独立的帖子 SPA 软跳、读写安全、请求 broker 或站点功能插件。
