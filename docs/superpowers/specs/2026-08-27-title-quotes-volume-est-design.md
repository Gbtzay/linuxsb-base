# 称号行情：成交估量

日期：2026-08-27  
范围：`plugins/title-quotes.user.js` 用挂单剩余变化大略估计成交笔数与件数；行情各称号行与大盘冷热榜展示；当前时间窗求和。  
非目标：真成交记录、K 图量柱、氧面板新配置、改采集 URL / `MERGE_MS` 12 小时同价规则的价侧、购买接口、氢、新 `ORDER` 模块。

## 问题

`/gacha_market` 没有公开成交。挂单有 `listing_id` 和剩余数量。两轮对比可以估「卖了几笔、几件」，但撤单和下架看起来也像卖完，必须写明这是估计。

## 方法

每轮采集在内存/store 留下上一份柜台 `book`：`{ t, rows: { [listing_id]: { key, qty } } }`。`key` 为 `名@稀有度`。

纯函数 `diffBook(prevRows, listings)`：

| 情况 | 件数 `sold` | 笔数 `fills` |
|---|---|---|
| 同一 `listing_id` 还在，剩余变少 | `prev.qty - curr.qty` | `+1` |
| 同一 `listing_id` 还在，剩余不变或变多 | 0 | 0 |
| `listing_id` 消失 | `prev.qty` | `+1` |
| 新 `listing_id` | 0 | 0 |

按 `key` 汇总成 `{ [key]: { sold, fills } }`。同一挂单一次剩余少 5 件 = **1 笔 5 件**。

没有上一份 `book`：本轮估量全 0，只写入当前柜台。上一份 `book.t` 距今超过 **3 小时**：整轮不估（避免关脚本几天后把积压差异一次算进「现在」），只刷新柜台。

把本轮各称号的 `sold` / `fills` 写进**新快照**的 `titles[k]`（缺省 0）。这是「相对上一轮」的增量，不是累计库存。旧快照没有这两字段时当 0。

`snapSig` **不**纳入 `sold`/`fills`（它们是增量，不是盘口状态）。12 小时同价合并仍看锚点 + `lo/hi/mid/n`。若本轮有任一称号 `sold>0` 或 `fills>0`：**禁止合并**，必须 push 新快照（卖 1 件同时新挂 1 件时 `n` 可能不变，否则估量会被吃掉）。

时间窗（本日 / 7 / 30 / 90）对该窗内快照的 `sold`/`fills` **求和**，归属后一条快照的时间。跨日边界那一档整段算进较新的一天，大略即可。

不画 K 量柱。不改巡检间隔。不请求购买。

## 外形

行情各称号行 `summary` 现有「最低 · 最高 · 上架 n 个」后面追加：

`估 F 笔 · S 件`

已下架行同样跟当前窗的估量（窗内曾经估到的仍累加）。`F`/`S` 为当前时间窗求和。

大盘冷热榜每一行涨跌数字旁同样跟 `估 F笔 S件`（短线/区间仍按现有价格涨跌排序，估量只展示不改排序）。新上/下架摘要不跟估量。

工具条下方（行情与大盘都有）一句：

`成交为挂单剩余变化的估计，含下架/撤单，不是真成交`

氧面板仍只有间隔、保留天数、打开浮层。

## 测试

`test/title-quotes.test.js`：

- `diffBook`：同 id 剩余 5→3 → 1 笔 2 件；消失 qty=4 → 1 笔 4 件；新 id 不计；两 id 各少 1 → 2 笔 2 件；同 id 少 5 → 1 笔 5 件。
- 无 `book` 或 `book.t` 超 3 小时：`pushSnap` 前估量为 0。
- `n` 不变但一笔卖掉一笔新挂：`snapSig` 相同也必须新写一条，且该快照带 `fills`/`sold`。
- 打开浮层、两轮带剩余变化的快照后，对应称号行匹配 `/估\s*1\s*笔/` 与件数；文案含「含下架/撤单」。
- 大盘冷热榜行也能看到 `估`；点 7 天只加总该窗快照。
- 原有 `n` 为上架数之和、12 小时同价推进、不请求购买等用例仍绿。
