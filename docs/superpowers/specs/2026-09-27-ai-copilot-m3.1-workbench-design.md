# AI 帖子副驾 M3.1：追踪数据工作台设计

## 状态

已获用户确认，待编写实施计划。M3.1 延续 M2 的观点分歧与方案对比，以及 M3 的问题追踪、证据变更和模型复核流程。

## 背景

M3 已经可以从“未解决问题”创建当前主题的追踪项，收集新楼层，保存候选证据，并在用户明确操作后接受模型状态建议。当前追踪项只有活动生命周期，缺少导出、归档、恢复、批量管理和可审计的操作历史。

M3.1 将把当前主题的追踪数据变成可管理、可备份、可合并的数据工作台，同时保持现有的本地存储和人工确认边界。

## 目标

1. 让当前主题的追踪数据可以导出为 JSON、Markdown 和两种 CSV。
2. 支持 JSON 导入预览和安全合并，避免覆盖本地较新的状态。
3. 支持追踪项归档与恢复；归档项停止接收新证据并从默认列表隐藏。
4. 支持批量归档、批量恢复和批量接受有效模型建议。
5. 保持“已确认解决”必须由用户显式确认的约束。
6. 保持只追踪当前主题、只保存本地数据、不增加外部网络或写入权限。

## 非目标

- 不建立跨主题追踪工作台或全局索引。
- 不做整体覆盖式 JSON 导入。
- 不自动把“可能已解决”变成“已确认解决”。
- 不回补追踪项归档期间的楼层。
- 不做后台跨主题巡检、自动通知或自动发帖。
- 不增加 `net` 或 `write` 权限。

## 已确认的产品决策

### 数据范围

- 导出、导入、归档和批量操作都限定在当前主题。
- 导出包含活动追踪项和已归档追踪项。
- JSON 导入只接受当前主题的文件；主题 ID 不匹配时拒绝。

### 导出格式

一次导出提供四个独立操作，避免浏览器阻止多个自动下载：

1. JSON：完整结构化数据，可再次导入。
2. Markdown：适合阅读、分享和人工检查。
3. `issues.csv`：每行一个追踪问题。
4. `evidence.csv`：每行一条基线、已确认或待复核证据。

### 归档与恢复

- 归档项从默认列表隐藏。
- 归档项停止接收实时新楼层，也不在显式重扫时加入新证据。
- 归档项原有证据、候选证据、模型建议和历史记录全部保留。
- 恢复后从恢复时点继续接收新证据，不自动回补归档期间楼层。
- 活动项和归档项通过筛选器分别查看。

### 批量操作

- 批量归档。
- 批量恢复。
- 批量接受有效模型建议。
- “已确认解决”继续按单项显式确认，不加入批量操作。

### JSON 导入

- 导入先校验并生成预览，用户确认后才写入。
- 相同追踪项按稳定 ID 合并。
- 证据按稳定键合并。
- 本地较新的状态和归档状态优先保留。
- 不覆盖本地扫描水位。
- 解析失败、主题不匹配、版本不支持或用户取消时不写入。

## 数据模型与迁移

### 存储版本

追踪存储从 v1 升为 v2，仍使用按主题的键：

```js
track:<topicId> = {
  version: '2',
  topicId: 123,
  scan: {
    seenKeys: [],
    lastFloor: 0,
    ts: 0,
  },
  items: [],
}
```

读取 v1 数据时补齐 v2 字段，不丢弃已有问题、证据和模型建议。迁移后的数据在下一次写入时持久化为 v2。

### 追踪项字段

在现有追踪项上增加：

```js
{
  archivedAt: 0,
  history: [],
}
```

- `archivedAt` 为 `0` 表示活动项，非零表示已归档。
- `history` 记录创建、证据加入、建议接受、建议驳回、人工确认、归档、恢复和导入合并等操作。
- `updatedAt` 继续作为排序和导入冲突判断依据。
- 每项历史记录固定上限为 100 条。

### 归档状态与扫描

事件处理和显式重扫继续使用稳定帖子键去重。归档项不会接收新证据；活动项的扫描和复核行为保持 M3 规则不变。恢复不会把归档期间的帖子自动加入候选队列，用户可以从恢复后的状态继续观察后续楼层。

### 批量接受建议

批量接受只处理同时满足以下条件的选中项：

- 存在有效建议。
- 建议状态属于 `待验证`、`有新证据`、`可能已解决` 或 `仍未解决`。
- 建议引用全部映射到当前追踪项的本地证据。

处理时把候选证据转入已记录证据，清除待确认建议并追加历史记录。不会生成“已确认解决”。

## 导出设计

### JSON

JSON 使用独立导出协议，避免和内部存储版本混淆：

```js
{
  schema: 'lsb-ai-copilot-tracking-export',
  version: 1,
  exportedAt: 0,
  topic: {
    id: 123,
    title: '主题标题',
    forumName: '版块名称',
  },
  tracking: {
    version: '2',
    topicId: 123,
    scan: {},
    items: [],
  },
}
```

导出包含完整追踪项、证据、建议、归档状态、历史记录和扫描快照。扫描快照用于审计和未来兼容；导入时不直接覆盖本地扫描水位。

### Markdown

Markdown 按以下顺序生成：

1. 主题信息和导出时间。
2. 活动追踪项。
3. 已归档追踪项。
4. 每项的问题、状态、基线楼层。
5. 已记录证据和待复核证据。
6. 最近模型建议。
7. 状态与操作历史。

楼层链接由当前主题路由和本地帖子 ID 生成。导出数据中的任意 URL 不直接进入页面 DOM。

### CSV

`issues.csv` 字段：

- 追踪项 ID
- 标题和问题
- 当前状态
- 是否归档
- 创建时间和更新时间
- 基线楼层
- 已记录证据数
- 待复核证据数
- 最近建议
- 来源摘要

`evidence.csv` 字段：

- 追踪项 ID
- 当前问题状态
- 是否归档
- 证据类型
- 稳定证据键
- 帖子 ID
- 楼层
- 作者
- 摘录
- 发现时间

CSV 使用 UTF-8 BOM，并对逗号、引号和换行执行标准转义。

## JSON 导入设计

### 校验流程

1. 用户选择 JSON 文件。
2. 检查文件大小，超过 5 MB 直接拒绝。
3. 解析 JSON 并校验导出协议、版本、主题 ID 和字段类型。
4. 对追踪项、证据、历史和建议执行现有规范化与数量上限裁剪。
5. 生成预览，不修改本地数据。
6. 用户确认后计算合并结果并一次写入。

### 合并规则

对于本地不存在的追踪项，导入完整记录。

对于相同追踪项 ID：

- `evidence` 按稳定键合并。
- `pendingEvidence` 按稳定键合并，并排除已经进入 `evidence` 的记录。
- `history` 去重后合并，并保留上限内的记录。
- `updatedAt` 较新的快照提供状态、归档状态、建议、标题和来源等元数据。
- 时间相同则本地数据优先。
- 本地扫描水位不被导入文件覆盖。
- 合并后的证据键加入本地去重集合。

预览明确列出新增追踪项、证据变化、状态冲突、归档冲突、非法记录和跳过记录。用户确认后显示新增、更新、合并、冲突和跳过数量。

### 安全边界

- 使用浏览器文件选择器和 `File.text()`，不上传文件。
- 下载使用 `Blob` 和浏览器下载链接。
- 不增加 `net` 或 `write` 权限。
- 导入文本按不可信内容处理，不将其作为 HTML 直接插入。
- 临时下载 URL、文件输入和预览状态在插件停用时清理。

## UI 设计

### 追踪页工具栏

增加：

- 活动 / 已归档 / 全部筛选。
- 全选当前筛选结果。
- 当前主题重扫。
- 导出菜单。
- 导入 JSON。

默认只显示活动项，归档项通过筛选器查看。

### 追踪卡片

每张卡片增加选择框、归档标记和操作状态。活动项保留“复核新证据”和“标为已确认解决”；归档项只显示“恢复”。

### 批量操作栏

有选中项时显示批量归档、批量恢复和批量接受有效建议。批量操作前显示影响数量和关键后果：归档会停止收集，恢复会重新接收新证据，接受建议会处理候选证据。

无有效建议的选中项不会被批量接受，并在完成统计中列为跳过。

### 导入预览

预览区域显示文件主题、协议版本、新增项、证据变化、状态冲突、归档冲突和被拒绝记录。只有点击“确认合并”后才调用存储写入。

路由切换时关闭预览并清除选择；旧主题的导入结果不能写入新主题。

## 错误处理与上限

- 下载失败：提示失败，不修改追踪数据。
- 文件过大、格式错误、版本不支持或主题不匹配：拒绝导入，不写入。
- 字段非法：在预览中列出并跳过，不影响其他合法记录。
- 存储写入失败：保留原数据和预览，允许重试。
- 批量操作部分失败：重新读取本地状态并报告成功、失败和跳过数量。
- 继续保留最多 50 个追踪项、每项 100 条证据和 2000 个已见帖子键。
- 每项最多 100 条历史记录，导入后继续执行相同裁剪规则。

## 测试与验收

必须覆盖以下行为：

1. v1 追踪数据迁移到 v2，原有内容不丢失。
2. 归档项停止接收实时证据和重扫证据。
3. 恢复后重新接收新证据。
4. 四种导出文件的内容、字段、中文编码和转义正确。
5. JSON 导入预览阶段不修改本地数据。
6. 相同 ID 的证据和历史正确合并。
7. 本地较新的状态和归档状态优先。
8. 非法文件、跨主题文件和超大文件被拒绝。
9. 批量归档、恢复和接受建议只作用于选中项。
10. 批量接受不会把问题直接标为“已确认解决”。
11. 页面切换和插件停用后无残留面板、文件输入、监听器或临时对象。
12. `npm test` 通过。
13. `npm run build` 通过。
14. `npm run verify:dist` 通过。
15. `git diff --check` 通过。
