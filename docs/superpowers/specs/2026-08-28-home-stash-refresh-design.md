# 存档还回：非主标签也巡检 + 离开时后台刷新首页存档

日期：2026-08-28  
范围：`plugins/live-feed.user.js`、`plugins/skin.user.js`。氧补丁号 +1。  
非目标：改氢 API、新开关、后台 GET 换掉**屏幕上**的主栏、给版块存档做同样的后台刷新、改选主协议。

## 问题

命中主栏存档时列表立刻上屏，新帖要等实时流 `cycle()`。两件事让「巡检」体感慢：

1. 本标签不是选主时 `shouldPoll()` 为假，`spa:view-restored` 不 `cycle()`，还回后干等。
2. 人不在首页时实时流巡的是当前页；首页那份存档冻着。点回来再拉 `/`，TTFB 仍是 0.7–2.6s。

## 方法

### 还回必巡一轮

`spa:view-restored`：`init()` 之后**不论是否主标签**都 `cycle()` 一轮。若当时有在途巡检，先等它结束（旧轮会因 `navGen` 作废），再巡当前页。本轮 `finally` 仍只在 `shouldPoll()` 时 `scheduleNext()`，跟标签不会变成常驻轮询。

`route:changed` 仍不得立刻 `cycle()`（避免软跳重复 GET）。

### 离开首页后刷新存档里的 `/`

皮肤在「当前主栏不是 `/`」且 LRU 里有 `/` 时，**30 秒**后 `api.net.raw('/', { queue: false, retry: 0 })`，剥 script、藏原生侧栏，把新主栏放进同一份 `/` 存档（`live: false`，`scrollY: 0`）。不写屏幕上的 outlet。无限滚动多出来的页会随这次替换丢掉——换新鲜首页，不要把后台 HTML 整页换进正在看的版块。

在途一次；标签隐藏时跳过这次 GET，记下待刷，可见后再刷。已经回到首页或 `/` 被 LRU 挤掉则丢弃结果。失败则下次间隔再试，还回仍用旧存档。

刚离开首页不要立刻拉：屏幕上挪走的那份就是刚看过的。间隔与实时流默认前台 `pollSec` 相同（皮肤写死 30s，不读实时流配置、不加开关）。

点回首页仍走存档命中（不等这次后台 GET 的点击路径）。后台已刷完则搬的是新节点；未刷完则搬旧节点，晚到的 GET 不得再改已上屏的主栏。

## 外形

无新开关、无新文案。点版块 / 回首页仍软跳。

## 测试

- 实时流让位成 follower 后，存档还回首页仍立刻多一次列表 GET。
- 首页 → 版块，间隔未到：不得因后台刷新多 GET `/`；点站名仍不 GET `/`，列表行仍是原节点。
- 首页 → 版块，放行 30s 定时器：应 GET `/` 一次；把存档换成带标记的 HTML 后点站名，主栏是新标记且不再 GET `/`。
- 现有「版块再回首页不 GET / 同一节点」「邀请中心预取」「route:changed 不立刻 cycle」必须仍过。
