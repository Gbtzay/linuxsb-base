# AI 已选目标回复设计

**状态：** 已实现并验证（2026-10-01）。  
**范围：** 在 AI 工作台从用户已选的站内主题或本人回帖生成回复草稿，并在审阅与二次确认后提交。  
**目标：** 让跨主题研究结果可直接转为可审阅的回复，同时保持目标来源明确、提交字段受限、请求不自动重放。

## 用户流程

1. 用户在研究候选中勾选一个主题或本人回帖作为操作目标。本人回帖必须来自已验证的本人回帖候选；主题必须来自当前研究候选。每个写计划只允许一个回复目标。
2. 用户在工作台明确要求针对已选目标回复。插件重新读取目标主题页，验证帖子 ID/楼层（如果目标是回帖）及原生回复表单；只把目标及必要的已选页面正文放入本次模型计划请求。
3. 模型返回独立的单步写计划。工作台显示主题标题、回复目标和完整正文；目标 key 与真实站点 ID 不写入持久化历史。
4. 用户点击执行后，写动作再次验证目标页和表单，并弹出第二次确认。确认卡说明选中楼层只作为草稿上下文，站点协议实际把回复发到所属主题。
5. 取消不提交。确认后通过基座 `api.actions.reply(topicId, body, { _csrf })` 向本站 `/reply_edit` 发一次请求；网络结果不确定时标记未知，不自动重试。

## 目标与证据边界

- 目标只能来自当前主题或用户在当前研究会话中明确选中的主题/回帖；搜索结果、页面正文和模型输出不能自行创建目标。
- 选中主题时读取该主题第一页；选中本人回帖时只读取并核验对应回帖所在页。一次计划最多一个发送目标，论坛正文最多使用 8,000 字符并作为不可信资料。
- 楼层引用仅用于生成与审阅回复，不声称服务端支持“回复某楼”。实际请求字段固定为 `_csrf`、`topic_id`、`body`。
- 跨主题目标需验证同源页面、主题 ID、POST `/reply_edit`、唯一有效 CSRF、匹配 `topic_id` 和唯一可用正文框；发送时再次读取验证。
- 写计划独占一个动作步骤；工作台执行前审阅正文，写动作执行时再次确认完整正文和目标。
- 目标 scope、临时 key、CSRF、帖子正文和真实目标 ID 不写入动作历史；路由变化、scope 过期或刷新中断均不重放。

## 组件

- `plugins/ai-copilot.user.js`：从用户显式选择创建短期回复目标 scope，向受限动作计划器提供匿名化目标 key、目标标签和有预算的已选证据；重新校验候选会话。
- `plugins/ai-write-actions.user.js`：新增针对已选目标的回复动作；验证本站回复表单，双重确认，通过固定的站内回复 API 单次提交。
- `plugins/ai-workbench.user.js`：在计划卡展示/核对目标与完整回复正文；写历史不保留临时目标 key。
- `test/ai-copilot.test.js`、`test/ai-write-actions.test.js`、`test/ai-workbench.test.js`：覆盖目标选择、协议校验、确认、请求字段、过期和刷新安全。
- README、插件版本与 Oxygen 构建产物：说明新工作流并更新分发版本。

## 不在本次范围

- 不生成或猜测服务端楼层回复字段。
- 不批量回复、不自动选择搜索结果、不读取未选主题、不自动发送草稿。
- 不自动处理附件、引用标记、@ 用户、富文本格式或站点响应后的自动刷新。

## 验收

- 未选候选、失效候选、目标/楼层不匹配、锁帖、缺少 CSRF、跨源 action 均不会生成可执行目标或发送 POST。
- 回复计划只能引用当前有效 scope 中的单一目标；模型不能提供站点 ID。
- 计划生成不写站点；第一次执行点击仍需动作提供方二次确认；取消不发送；确认最多发送一次且字段精确为 `_csrf`、`topic_id`、`body`。
- 确认期间页面/目标/正文表单状态变化时停止发送；请求结果未知不会自动重放，刷新后的历史不包含目标 key 或 CSRF。
- 完整测试、构建、发行产物校验及 `git diff --check` 通过。
