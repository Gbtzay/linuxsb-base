# AI 副驾 0.2：楼层证据与新回复摘要设计

日期：2026-09-27

## 目标

在现有 `ai-copilot` 首版的问答、讨论分析和回复草稿之上，增加可信的楼层证据展示和“只分析新回复”模式；同时让套件产物具备可验证的新鲜度，避免源码更新后继续发布旧 `dist`。

## 范围

### M0：发布完整性

- 新增 `scripts/check-dist.mjs` 与 `npm run verify:dist`。
- 检查 Hydrogen 产物版本与 `src/core.js` 一致。
- 检查 Oxygen banner、套件中心和 LTS 版本一致。
- 检查 `ORDER` 中的每个插件正文都出现在 Oxygen 产物中。
- 检查 `ai-copilot` 存在于 Oxygen、不会进入 LTS。
- 版本：`ai-copilot` `0.2.0`，Oxygen/LTS `1.0.114`，Hydrogen 保持 `0.1.41`。
- 更新 README、规范和测试招募/已知问题文档中的正式版本。

### M1：楼层证据

- 模型提示词要求事实尽量使用 `[#N]` 格式引用楼层，不得捏造楼层。
- 模型返回后解析 `[#N]`，根据当前上下文生成引用记录：楼层、作者、短摘录、帖子锚点。
- 结果面板增加“引用楼层”区域：已知楼层显示可点击链接，未知楼层显示“当前采集范围没有此楼层”。
- 引用记录进入缓存；请求指纹加入证据协议版本，避免回放首版无引用缓存。
- 复制按钮仍复制模型原文，不把 HTML 链接写进剪贴板。

### M1：新回复摘要

- 副驾增加“新回复”模式。
- 每个主题维护本地状态 `digest:<topicId>`：起点楼层、待处理楼层摘要、更新时间。
- 首次在主题启用时，以当前最高楼层建立起点，不把历史回复误报为新回复。
- 基座发出 `topic:posts-added` 时，将新楼层放入待处理队列；分页采集时也会按起点补齐。
- 用户可手动“以当前楼层设为起点”，清空待处理队列。
- 点击“总结新回复”只把待处理楼层放入 `<new-replies>` 区块；旧正文不作为新回复交给模型。
- 模型请求成功后才推进起点并清空队列；失败、超时或空结果均保留队列。
- 结果显示新回复数量和楼层范围，并复用楼层证据区域。

## 数据与接口

`ai-copilot:debug` 增加以下调试能力：

```js
{
  citations(text, posts, topicId),
  digestState(topicId),
  pendingReplies(topicId, posts),
  markDigestRead(topicId, posts),
}
```

引用记录结构：

```js
{
  floor: 12,
  postId: 345,
  authorName: '用户',
  excerpt: '正文前 120 个字符',
  href: '/topic/1#post-345',
  known: true,
}
```

新回复状态结构：

```js
{
  floor: 12,
  postId: 345,
  authorName: '用户',
  content: '正文',
  ts: 1720000000,
}
```

状态最多保留 100 条待处理回复；只保留当前主题的本地插件存储，不上传站点。

## 安全边界

- 论坛正文、引用和作者名仍是不可信数据；它们只进入 `<forum-content>` 或 `<new-replies>`。
- 生成的链接只由本地主题 ID、帖子 ID 和固定路径构造，不信任模型输出的 URL。
- 摘录使用文本转义，不把模型输出当作 HTML。
- 副驾不申请 `net` 或 `write`，不自动填充或提交站内回复。

## 验收标准

- `npm run build` 成功，`npm run verify:dist` 成功。
- 新增测试覆盖：引用解析、已知/未知楼层链接、新回复队列建立/清除/失败保留、分页补齐、首访不误报、产物新鲜度。
- 全量 `npm test` 通过。
- `ai-copilot` 在 Oxygen 产物中可见，LTS 产物中不可见。
- 当前工作区中既有的站点适配、皮肤和 topic-marks 改动不被回退。

## 非目标

- 不做自动发帖、自动点赞或自动收藏。
- 不做后台全站抓取、embedding 索引或跨用户共享会话。
- 不把“新回复摘要”变成实时自动调用；模型请求仍由用户点击触发。
