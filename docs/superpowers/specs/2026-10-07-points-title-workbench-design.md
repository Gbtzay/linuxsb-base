# 积分-称号工作台设计

- 日期：2026-10-07
- 状态：已确认设计，待写实现计划
- 范围：Oxygen 工作台聚合、积分快照、称号行情和 UR 合成规划

## 1. 目标与已确认决策

新增 `points-title-workbench`，作为积分、称号行情和 UR 合成规划的唯一默认功能入口。工作台是一个沿用称号行情样式的悬浮窗口，支持拖动、调整大小、收起、关闭、位置持久化、视口边界修正和窄屏单列布局。

窗口内部有四个视图，默认打开“总览”：

1. 总览
2. 积分
3. 行情
4. UR 规划

用户已经确认的产品决策：

- 视觉布局采用 A：宽屏平衡双栏，窄屏改为单列。
- 每次打开工作台都自动刷新全部数据源。
- 刷新期间先显示最近成功缓存，并按来源逐项更新。
- 单个来源失败只停用受影响的路线，其他结果继续显示。
- 单个来源最多等待 10 秒，超时后进入明确错误状态。
- 同时显示“不计库存”和“计入当前库存”两种结果。
- 每种结果同时显示最低挂单、中位价估算和抽取期望三类路线。
- 最低挂单必须按实际挂单数量逐单取货；中位价是估算，不代表一定能买齐。
- 工作台进入 Oxygen，顺序为 `points-ledger` → `title-quotes` → `title-forge-planner` → `points-title-workbench`；不进入 LTS。
- 旧的积分趋势、全局称号行情和 UR 规划独立功能入口移除或迁移；三个插件保留配置能力、数据采集能力和正式只读接口。
- 称号交易页中的行情嵌入继续保留。
- 所有请求只读，不新增购买、抽奖或合成写请求。

## 2. 范围边界

### 2.1 本次包含

- 新增聚合工作台插件及其悬浮窗口。
- 将 `skin` 的“积分趋势”和“称号行情”入口合并为“积分-称号”，入口调用 `points-title-workbench:open`。
- 让 `points-ledger` 提供积分快照序列，隐藏其独立功能入口但保留配置和正式 RPC。
- 让 `title-quotes` 提供完整性可验证的行情快照和按需刷新接口；保留交易页嵌入。
- 让 `title-forge-planner` 提供页面刷新结果和纯计算 RPC，隐藏独立 UR 面板入口。
- 修复市场分页不完整、部分快照被当作完整行情、挂单数量不足判断错误和中位价文案歧义。
- 为加载、超时、缓存、局部失败、挑战页、登录页和页面格式变化提供可见状态。

### 2.2 本次不包含

三段式顶栏 AI 操作台、三段式左上角站点文案、三段式右侧 AI 栏、iOS 27 单画布 CF 挑战页白屏、三段式返回首页个人资料卡残留等既有 UI 问题不纳入本工作台设计，也不在本轮顺带修改。

## 3. 模块职责与边界

### 3.1 `points-title-workbench`

工作台插件负责：

- 悬浮窗口的创建、拖动、缩放、收起、关闭和边界修正。
- 四个内部视图和总览摘要。
- 打开时的缓存首屏、刷新协调、来源状态和超时处理。
- 调用数据提供者的正式 RPC。
- 持久化聚合快照、窗口矩形和来源时间。
- 将标准化输入交给规划器计算，并根据积分显示可行路线或最小缺口。

工作台不直接依赖任何插件的 debug RPC，不解析站点页面，不提交站内表单。

### 3.2 `points-ledger`

继续保存积分快照序列并提供现有只读 RPC：

```text
points-ledger:series({ days }) -> [{ t, p }]
```

当前积分直接读取基座身份数据 `api.me.points`。积分趋势视图复用该序列。插件的采样间隔和保留天数配置继续有效，但不再显示独立的“积分趋势”功能入口。

### 3.3 `title-quotes`

继续负责称号行情的分页采集、聚合和交易页嵌入。全局行情悬浮入口迁移到工作台，不再作为独立功能入口显示。

现有 `title-quotes:market-data` 扩展为可验证的只读快照：

```js
{
  schema: 2,
  fetchedAt: Number,
  coverage: {
    complete: Boolean,
    expectedPages: Number,
    fetchedPages: Number,
    failedPages: Number,
    challengePages: Number,
  },
  listings: [
    { key: String, price: Number, qty: Number },
  ],
  titles: {
    [key]: { rarity: String, lo: Number, hi: Number, mid: Number, n: Number },
  },
}
```

新增正式只读刷新接口：

```text
title-quotes:refresh() -> market snapshot or source error
```

刷新接口复用现有采集中的单飞请求；工作台打开、用户点击刷新和行情插件自身的定时采集不会并发抓取同一轮市场数据。只有 `coverage.complete === true` 的快照可以作为完整最低挂单数据；旧的完整快照可以标记为过期后继续使用。

### 3.4 `title-forge-planner`

保留配方、抽取池、库存解析器和路线计算器，改为后台计算服务，不再注册独立的 UR 规划面板。正式接口分为两部分：

```text
title-forge-planner:refresh() -> {
  sources: {
    recipes: SourceState,
    gacha: SourceState,
    inventory: SourceState,
  },
  data: {
    recipes,
    gachaPools,
    titleCatalog,
    inventory,
    inventoryAvailable,
  },
}
```

`refresh` 仍读取 `/gacha_recipes`、`/gacha` 和 `/gacha_profile`，但每个来源独立超时、独立缓存和独立报告状态。它不把登录页、挑战页、空页面或字段缺失转换成空数组成功结果。

纯计算接口不产生网络请求：

```text
title-forge-planner:calculate({
  recipes,
  market,
  gachaPools,
  inventory,
  points,
}) -> {
  modes: {
    noInventory: { targets, summary },
    inventory: { targets, summary },
  },
  points,
}
```

工作台只调用这两个正式接口，不读取 `title-forge-planner:debug`。

## 4. 数据流与刷新生命周期

### 4.1 打开工作台

1. 入口调用 `points-title-workbench:open`。
2. 工作台读取自己的最近聚合快照，立即绘制总览；没有缓存时显示有限的加载状态。
3. 工作台创建一个单飞刷新 Promise。重复点击入口或刷新按钮只复用该 Promise。
4. 并行触发当前积分读取、`points-ledger:series`、`title-quotes:refresh` 和 `title-forge-planner:refresh`。
5. 每个来源完成后独立写入工作台缓存并重绘来源状态；不清空其他已经显示的数据。
6. 所有来源完成或超时后，调用一次 `title-forge-planner:calculate`，更新两种库存模式和总览摘要。
7. 保存 `{ savedAt, sources, data, plans }` 聚合快照，供下一次打开首屏使用。

### 4.2 来源状态

每个来源都使用同一结构：

```js
{
  status: 'idle' | 'loading' | 'ok' | 'partial' | 'stale' | 'unavailable',
  fetchedAt: Number | null,
  error: String | null,
  stale: Boolean,
  issues: Array,
}
```

`stale` 只表示本轮刷新失败但仍有上次成功数据。使用旧数据继续计算时，结果区域同时显示数据更新时间，不能伪装成刚刚获取的数据。

### 4.3 超时和取消

每个来源使用独立的 10 秒超时控制器。超时会结束该来源的等待并继续处理其他来源。窗口关闭或插件销毁时取消未完成请求。刷新 Promise 必须最终进入完成或错误状态，不允许由异常路径留下永久的 loading 状态。

## 5. 路线计算规则

### 5.1 两种库存模式

- `noInventory` 使用空库存，回答“从零开始需要多少积分”。
- `inventory` 先扣除已确认的库存，回答“按当前库存还需要多少积分”。
- 库存来源没有可靠数量时，仍显示 `noInventory`；`inventory` 显示“无法确认库存数据”，不把库存当作零。

### 5.2 最低挂单路线

对每个材料：

1. 先扣除对应库存。
2. 按单价升序、原始顺序稳定排序挂单。
3. 按每个挂单的真实 `qty` 逐单取货，直到满足需求。
4. 任一材料的挂单总量不足时，返回 `unavailable` 和具体缺口，不返回零成本。
5. 费用只加入一次；步骤保留每个单价层的数量和成本。

因此，`路人甲@N` 需要 100 个且存在 36 个 × 10 的挂单时，规划器会继续读取后续挂单。只要全量完整快照能覆盖 100 个，就显示实际最低挂单路线；不能覆盖时显示还缺多少个。

### 5.3 中位价估算

对每个材料使用行情聚合中的 `mid` 乘需求数量并加合成费用。该路线只表达统计估算，不检查实际挂单数量，也不声称可以按中位价一次买齐。它可以低于最低挂单路线，界面必须使用“中位价估算”标签区分两者。

### 5.4 抽取期望路线

只使用概率和为完整分布的抽取池。通过有限状态期望计算重复抽取、共享奖池和无进展概率；概率不完整、抽取成本缺失或需求无法被概率池覆盖时，路线为 `unavailable`。可用路线显示期望抽取次数和期望积分，并固定显示“期望值，不保证实际结果”。

### 5.5 积分摘要

对每个 UR 配方计算三类路线，选择成本最低的有效路线作为该目标的 `best`。每种库存模式分别：

- 过滤 `status === 'ok'` 且成本不超过当前积分的目标，选择最低成本路线作为 `bestFeasible`。
- 没有可行路线时，从有效路线中选择积分缺口最小者作为 `nearest`。
- 积分未知时返回 `state: 'unknown'`，保留成本结果但不显示虚假的剩余或缺口。
- 所有路线都不可用时显示“无法判断”和对应来源错误。

## 6. 工作台视觉与交互

### 6.1 窗口

- 标题栏显示“积分-称号工作台”和可拖动提示。
- 标题栏提供收起、关闭和状态按钮。
- 窗口默认使用平衡双栏；标题栏拖动和右下角缩放沿用称号行情浮层的交互。
- 保存窗口的 `left/top/width/height`，打开时将其限制在当前视口；保存值非法或超出范围时恢复安全默认矩形。
- 窄屏使用 `width: calc(100vw - 16px)` 的单列窗口，内容区域独立滚动，标签可以横向滚动但不换成多行挤压内容。

### 6.2 总览

总览从上到下显示：

1. 当前积分和最近变化。
2. 行情样本数量、分页覆盖和更新时间。
3. UR 规划进度或最小积分缺口。
4. 积分趋势与行情速览双栏。
5. 不计库存和计入库存的最佳结果摘要。

### 6.3 其他视图

- 积分视图复用快照序列的趋势图和最近变化。
- 行情视图显示最低挂单、中位价、行情覆盖和来源时间；缺页时明确显示快照不完整。
- UR 规划视图按目标分组显示两种库存模式，每个目标固定列出最低挂单、中位价估算和抽取期望，并可展开步骤。

### 6.4 入口

`skin` 的功能列表改为一个：

```js
{ plugin: 'points-title-workbench', rpc: 'points-title-workbench:open', label: '积分-称号' }
```

三个提供插件不再作为独立功能入口出现，但它们的配置仍由插件设置系统保留。交易页内的行情嵌入不通过该入口控制。

## 7. 错误文案和安全边界

固定用户可见文案：

- 配方、抽取或库存页面没有可识别结构：`页面格式无法识别`
- 库存页被挑战、未登录或数量字段无法确认：`无法确认库存数据`
- 没有完整有效的 UR 配方：`合成表数据不足`
- 概率池不完整：`抽取路线：数据不足`
- 行情分页失败或挑战页导致覆盖不完整：`称号行情数据不足`

规则：

- 挑战页、登录页和空页面不能被解析成零库存、零概率或空配方成功状态。
- 动态称号名、来源状态、错误文案和步骤文本全部经过转义。
- 不读取或提交购买、抽奖、合成表单，不注册写请求监听器。
- 所有数组长度、页数、数量和成本都在解析、计算和渲染前检查有限性和上限，避免 `Invalid array length`。

## 8. 测试与验收

### 8.1 单元测试

- `points-ledger` RPC 返回快照序列。
- `title-quotes` 完整覆盖、缺页、挑战页和空快照状态。
- 多挂单逐单取货：36 个 × 10 之后继续取后续挂单。
- 中位价估算可低于最低挂单但不改变最低挂单步骤。
- 库存先抵扣，库存不可确认时不当作零。
- 抽取重复结果、共享奖池、概率不完整和无覆盖材料。
- 两种库存模式的可行路线、最小缺口和积分未知状态。
- 解析异常和超大/非法页数不触发数组长度异常。

### 8.2 集成测试

工作台测试覆盖：

- 有缓存时首屏立即显示且刷新状态可见。
- 四个来源并行刷新，完成顺序不影响最终结果。
- 单源超时后其他路线仍显示。
- 无缓存时所有来源失败会在 10 秒内进入错误状态。
- 重复打开和重复点击刷新不产生并发刷新。
- 行情来源失败时仍保留配方和积分视图；库存失败时仍显示不计库存模式。
- 请求记录中没有 POST、购买、抽奖或合成 endpoint。

### 8.3 浏览器和套件验收

- Oxygen 的入口只有“积分-称号”，打开默认“总览”。
- 工作台可拖动、缩放、收起、关闭，刷新后位置和尺寸恢复并保持视口内。
- 宽屏为平衡双栏，窄屏无横向溢出和选项/卡片挤压。
- 交易页行情嵌入仍存在。
- `points-title-workbench` 出现在 Oxygen，不出现在 LTS。
- 构建、全量测试、dist 新鲜度和差异检查通过。

## 9. 实现顺序

1. 为 `title-quotes` 补充覆盖信息、完整快照验证和按需刷新 RPC。
2. 将 `title-forge-planner` 的刷新和纯计算能力整理为正式 RPC，拆除其独立入口但保留配置与测试接口。
3. 为 `points-ledger` 补齐工作台需要的正式只读摘要，保留现有序列 RPC 兼容性。
4. 新增 `points-title-workbench`，先实现缓存、来源状态、超时和刷新去重，再接入四个视图。
5. 更新 `skin`、Oxygen 顺序、版本文档和构建产物；确认 LTS 不含工作台及其专属入口。
6. 按单元、集成、浏览器和套件验收顺序运行测试。

该设计不改变 AI 操作台、三段式 UI 或 iOS 27 单画布的其他既有工作范围。
