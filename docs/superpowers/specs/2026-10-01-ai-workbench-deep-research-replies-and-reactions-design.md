# AI 工作台深读、本人回帖与站内互动设计

- 日期：2026-10-01
- 状态：设计已确认，规格待用户审阅
- 涉及模块：`ai-workbench`、`ai-copilot`、站点解析层、独立 `ai-write-actions` 插件

## 1. 目标

在现有 AI 工作台中同版扩展三项能力：

1. 对用户选中的主题继续读取后续页，并为读取到的楼层提供可验证引用。
2. 检索本人发布的回帖；只有用户明确选择的数据源和回帖正文才进入 AI 分析。
3. 扩展主题与回帖的点赞、收藏和投币操作；目标与参数由本地数据约束，执行前由用户确认。

三项能力分别验收。深读和个人回帖属于只读数据流程；站内互动沿用独立写权限插件，与只读工作台能力分离。

## 2. 设计选择

### 2.1 架构方案

- **推荐：读取与写入分开。** `ai-copilot` 负责检索计划、主题/回帖读取、引用映射；`ai-write-actions` 负责站点互动写动作，并保留独立 `write` 权限。工作台展示两类流程。
- **把所有能力合并到工作台核心。** 调用路径较少，但数据读取与站点写入的权限边界混在一起，较难审查。
- **仅模拟站点按钮。** 更贴近用户手动操作，但无法稳定处理从本地候选中选出的跨主题目标，也难以在执行前验证服务端切换状态。

沿用现有独立写动作架构，在其上增加受限的点赞、收藏和投币动作。

### 2.2 共同边界

- 模型只能提出结构化计划、搜索词或候选楼层建议；本地逻辑负责验证来源、目标 ID、楼层映射、动作类型和参数。
- 页面内容、主题标题、回帖正文和其它站点文本均是不可信材料，不可作为操作指令。
- 用户需要明确要求执行写动作。分析、起草、建议或引用站点正文中的操作语句都不能触发写入。
- 每个写计划仅包含一个目标和一个写动作。多目标操作需要逐个生成计划并逐个确认；首版不提供批量写入。
- 页面、正文和个人数据仅按请求在内存中处理，不自动保存候选或正文，不在刷新后自动重放读取和写操作。

## 3. 已确认的只读能力

### 3.1 已选主题后续页深读

现有跨主题资料流程继续负责搜索或个人来源候选、用户选择最多 3 篇主题以及读取第一页。用户要继续追踪已选主题时：

- 每次点击只读取一篇主题的一页，页码由本地页面解析器提供；固定的本站主题路由由本地生成。
- 已读取页面共同使用 18,000 字符预算。超出预算时保留截断状态，不声称分析了未读取内容。
- 每个楼层保留本地解析得到的主题 ID、页码、楼层号和可用的站内链接映射。引用只能指向本次实际读取的楼层。
- 页面正文仅保存在当前研究会话内存中，不写入本地对话历史。刷新后不自动重新抓取；用户可以重新手动读取。
- 某页读取失败只标记该页失败；已有成功读取的证据仍可用于回答，并说明回答范围。

### 3.2 本人回帖资料源

新增个人资料源 `my-replies`，与本人主题、本人收藏使用相同的明确授权原则：

- 仅当用户明确提到“我的回帖”等本人回帖请求，或在工作台主动选择本人回帖数据源时读取。
- 本人身份只能取自当前本地登录状态。计划器不得提交用户 ID；身份缺失或无法验证时停止请求。
- 候选页由用户逐页手动加载，不遍历后续页面。候选按本地解析出的回帖/楼层 ID 去重，并提供主题标题、楼层和作者等必要信息供用户挑选。
- 用户最多选择 3 条回帖。仅所选回帖进入正文读取和回答请求；本地通过主题与楼层映射读取对应楼层正文。
- 未选回帖正文和其它个人页正文不进入模型请求。候选、正文和原始个人页 URL 不持久化。
- 引用由本地把主题 ID 与楼层号映射成固定站点链接。模型给出的楼层或 ID 若不在本次本地选择集合中，不创建引用或链接。

## 4. 站内互动写操作

### 4.1 首版动作和目标

首版新增：

- 主题点赞和取消点赞。
- 主题收藏和取消收藏。
- 回帖点赞和取消点赞。
- 对主题或回帖投币。

主题目标限当前打开主题，或用户从本地已显示的候选中手动选定的主题。候选可来自站内搜索以及用户明确启用的个人数据源。模型不能自行创造主题 ID。

回帖目标只限当前打开主题或已选主题中，页面解析或已读证据实际包含的回帖。模型可以根据已读内容推荐楼层，但必须由用户在确认卡中逐项选定。楼层 ID 由本地楼层映射解析，模型输出的任意回帖 ID 不可直接用于写请求。

### 4.2 计划与用户确认

1. 用户明确提出写操作后，模型生成一个待审阅的受限计划。计划本身不发出请求。
2. 本地把计划映射到唯一的、已经验证的主题或回帖目标。目标不存在、未由用户选中或无法映射时拒绝该计划。
3. 工作台显示确认卡，至少包括主题标题、目标类型、回帖楼层（若适用）、动作和预期结果。
4. 收藏/点赞确认卡同时显示经验证的当前状态与期望状态。投币确认卡显示主题或回帖目标、站点允许的档位和实际选择的投币数量；若站点明确提供积分消耗信息则一并显示，不能把投币数量猜作积分成本。
5. 投币金额只能取目标页面给出的有效档位。用户未指定金额时，必须由用户在确认卡选择；模型不能自行替用户挑选金额。指令中的金额不在有效档位中时，不执行并要求选择有效档位。
6. 确认卡提交是第二次确认。取消不发送请求。一次写计划只执行一个动作，不串联只读/导航/其它写步骤。

### 4.3 切换状态验证与提交

站点收藏和点赞接口采用切换语义，因此操作按“期望状态”表达，不能盲目重复切换：

- 在展示确认卡前，本地从同源页面解析目标当前状态和可用档位；解析结果采用明确的已选/未选/未知状态，缺少标记时记为未知。
- 用户确认后，在发送请求前再次读取或验证目标标识、当前状态和档位。若目标发生变化、当前状态与预览不同、用户已经达成期望状态或状态不明，则取消本次提交并刷新确认卡或说明原因。
- 对于已明确处于期望状态的收藏/点赞请求，返回“已满足”，不调用切换接口。
- 只有状态明确且与期望状态不同，才向固定本站写路由发出一次经白名单校验的请求。模型不提供路由、CSRF 或任意表单字段。
- 超时、页面刷新或响应无法证明成功时标记为结果未知，不自动重试。提示用户检查站点当前状态；用户重新发起后重新解析状态、重新确认。
- 投币是有成本的写操作。提交只使用用户确认的有效档位，每次只发出一次请求；失败或结果未知时不自动重发，避免重复扣分。

### 4.4 权限与模块职责

- `ai-copilot` 提供深读和本人回帖检索的只读能力，负责受限计划验证、来源授权、字符预算、引用映射和请求级内存状态。
- 站点适配层解析分页、主题、本人回帖、楼层及互动控件的状态和档位。DOM 选择器与状态解释集中在适配层。
- `ai-write-actions` 保持独立 `write` 权限，在现有回复、发帖和签到动作之外增加点赞、收藏和投币的目标校验、确认卡及本站写请求；既有动作的行为和确认流程不变。
- `ai-workbench` 呈现来源选择、候选与加载状态、深读结果及写动作确认；会话变化或导航后的迟到响应不得覆盖当前状态。
- 不为本站互动新增站外 `net` 权限，不把写权限授予只读检索插件。

## 5. 错误处理和隐私

- 身份不可用、候选不属于本地来源、楼层映射无效、状态未知、页面跨主题、档位无效或目标内容已变化：拒绝写入并显示可理解的原因。
- 搜索或个人回帖分页无结果时，不请求主题正文。用户未选择回帖时，不读取其正文。
- 部分页面读取失败时，回答只根据成功加载的页面生成，并标明缺页；所有读取失败时不调用回答模型。
- 请求正文只包含用户选择的主题页/回帖和必要的主题、楼层元数据。未选候选、用户 ID、CSRF、原始 URL 和完整 DOM 不发送给模型。
- 不把候选、主题正文、个人回帖、待执行请求或写入凭据写入本地对话历史。刷新时将进行中的读取标成中断；写操作若结果未知，禁止自动重放。
- 页面导航或会话切换后，旧请求结果不得更新新会话；同一写确认卡只能提交一次。

## 6. 验收标准

### 深读

- 首次选读仍最多 3 篇主题；后续每次显式操作只读一篇主题的一页。
- 所有已读主题页共享 18,000 字符预算，实际楼层引用保持正确；未读取页不能成为事实证据。
- 超预算、缺页、刷新中断和部分失败状态在工作台可见，且不会自动重新请求。

### 本人回帖

- 自动检索请求不能触发本人回帖读取；明确请求或主动选择来源才能访问本人页面。
- 身份只从本地状态取得；候选可手动加载下一页，每次最多读取一页；最多选 3 条回帖。
- 只有用户选择的回帖内容进入回答模型，引用只能映射到已读取的实际楼层。

### 写操作

- 当前主题和手动选择的本地候选可作为主题目标；回复目标必须先在本地解析并由用户逐条选定。
- 用户明确要求写操作后才生成写计划；页面正文提示、模型自造 ID、模型自选金额均不能触发请求。
- 计划显示正确目标、当前状态、期望状态、投币档位和站点明确披露的积分信息；取消确认不发请求。
- 对状态未知、目标变化、无效档位、已满足的目标状态和无效映射，验证分别是停止、停止、停止、无写请求和拒绝执行。
- 每个写计划最多一个目标、一个写动作；运行中/响应丢失/刷新恢复均不自动重试或重放。
- 点赞/收藏重复请求不会盲目反转状态；投币只使用页面档位并在不确定结果时禁止自动重发。

### 回归

- 现有站内搜索、个人主题/收藏、当前页查询、帖子副驾、追踪、回复/发帖/签到和右栏刷新恢复继续工作。
- 氢壳与非氢壳工作台入口不变；LTS 的既有排除边界不改变。
- 自动化测试覆盖来源授权、分页、选择上限、共享字符预算、楼层引用、动作权限、状态再验证、确认取消、单次提交和不自动重放。
