# AI 工作台 M11：统一可信阶段与可解释性设计

- 日期：2026-10-01
- 状态：用户已确认设计，待编写实施计划
- 范围：帖子副驾、追踪、跨主题研究、自然语言操作台、站内写动作

## 1. 目标

M11 为所有 AI 流程建立统一的可验证阶段协议，让右栏工作台能够清楚说明：

1. 当前实际执行了哪些阶段、读取了哪些范围；
2. 哪些结果由本地解析器或站点状态验证，哪些仍然未知或部分完成；
3. 为什么某个计划被收窄、降级、拒绝或停止；
4. 刷新、路由变化、失败和未知写回执之后，用户可以采取什么安全的下一步。

“思考过程”只表示本地可验证的处理过程，不展示模型隐藏推理、逐字思维链或原始站点材料。

## 2. 已确认方案

采用“统一可验证阶段协议 + 工作台渲染器”：

- 基座提供纯本地 `trace.v1` 校验、归一化和脱敏能力；
- 各 AI 插件按统一阶段发出安全事件；
- 工作台按会话和轮次聚合事件，默认显示紧凑时间线，用户可展开证据详情；
- 已知计划变体在本地兼容；未知版本降级为普通只读查询并显示限制；
- 未知版本若包含写动作或无法安全降级，则拒绝执行并要求重新生成；
- 完整事件只保留在当前内存流程中，历史只保存受限阶段摘要。

## 3. `trace.v1` 事件协议

每条事件只允许以下字段：

```js
{
  id: '阶段序号',
  flowId: '本次请求或动作 ID',
  stage: 'plan|scope|read|validate|answer|execute|check|limit',
  state: 'pending|active|complete|failed|unknown|skipped',
  title: '短标题',
  summary: '最多 200 字的可验证摘要',
  evidence: 'verified|partial|unverified',
  counts: { selected: 0, read: 0, matched: 0, citations: 0 },
  citations: ['本地已验证引用 ID'],
  reasonCode: '可选的固定错误或限制代码',
  startedAt: 0,
  finishedAt: 0
}
```

### 3.1 状态和事实约束

- 阶段只有在对应本地操作真正完成后才进入 `complete`。
- 写请求响应不确定时进入 `unknown`，不得渲染成成功。
- `summary`、`counts` 和 `citations` 由本地代码生成；模型不能直接声明阶段已完成。
- 状态迁移由协议校验器限制：`pending -> active -> complete|failed|unknown|skipped`；已结束状态不可回到活动状态。
- `citations` 只能引用本地当前流程已验证的引用 ID；未知引用被丢弃并增加对应限制事件。
- `reasonCode` 使用固定枚举，不能把模型或站点原始长文本当作错误码。

### 3.2 数据安全约束

事件和历史不得包含：

- 模型隐藏推理或逐字思维链；
- 原始响应、完整 DOM、Cookie、CSRF、完整原始 URL；
- 未选择候选的正文、个人资料正文、临时目标映射或写入凭据；
- 未经本地验证的主题 ID、回帖 ID、楼层链接或站点状态。

校验器丢弃未知字段，截断超长字符串和数组，并对 `summary` 做文本安全处理。工作台历史最多保留每轮 6 条阶段摘要，每条摘要最多 200 字；完整正文和研究账本继续只存在当前内存会话。

## 4. 模块边界与数据流

### 4.1 基座

新增纯本地 `src/ai-trace.js`，并由 `src/core.js` 以 `api.ai.trace` 暴露：

- `validateEvent(event)`：校验字段、状态和数量上限；
- `sanitizeEvent(event)`：截断并丢弃敏感或未知字段；
- `transition(previous, next)`：执行有限状态迁移；
- `normalizePlanVersion(raw, context)`：兼容已知变体，或生成安全的只读降级结果；
- `reasonCode(code)`：返回固定错误/限制文案。

该模块不发送网络请求，不保存数据，不增加权限。

### 4.2 AI 副驾和研究

`ai-copilot` 将计划生成、查询范围、主题/回帖读取、引用校验和回答请求映射为 `plan`、`scope`、`read`、`validate`、`answer` 事件。已有研究会话、字符预算和引用白名单保持不变。

### 4.3 工作台

`ai-workbench` 按 `flowId` 和轮次聚合事件：

- 处理中显示最近活动阶段；
- 完成后折叠为一行范围与引用摘要；
- 展开后显示事件顺序、验证状态、限制和本地引用；
- 路由或会话变化时，旧事件只能写回原轮次，不能覆盖当前会话；
- 历史只持久化安全摘要，不持久化完整事件账本、研究正文或短期目标。

### 4.4 写动作

`ai-write-actions` 将二次确认、提交、站点回执和只读结果检查映射为 `execute`、`check` 和 `limit` 事件：

- `pending`/`active` 表示尚未产生站点结论；
- 明确站点失败为 `failed`，停止后续步骤；
- 网络异常、5xx、HTML、缺少 `ok` 或响应丢失为 `unknown`；
- `unknown` 只能显示一次安全检查入口，不自动重发写请求。

## 5. 计划兼容与安全降级

`normalizePlanVersion(raw, context)` 的处理顺序：

1. 本地检查版本、字段白名单、动作目录、页面范围和权限；
2. 将已知的字段别名和意图同义词归一到当前计划结构，并记录 `plan-normalized` 警告；
3. 对未知版本尝试生成普通只读查询，只保留用户问题、当前允许的数据范围和安全的查询关键词，并记录 `plan-downgraded` 限制；
4. 若原计划包含写动作、任意 URL、未验证目标、未知权限或无法确定读取范围，则返回 `plan-unsupported`，不执行、不重放，提示用户重新生成。

降级结果必须在时间线和回答摘要中明确显示，不能让用户误以为原计划的全部能力已经执行。

## 6. 右栏交互

- 处理中默认展开阶段条，使用“读取范围”“校验引用”“生成回答”等事实文案；
- 完成后显示紧凑摘要，例如“读取 2 个主题 · 校验 5 条引用 · 1 条证据缺口”；
- 详情面板显示阶段状态、摘要、数量、验证状态、限制原因和可点击引用；
- 未知计划版本显示“已降级为普通只读查询”，并列出未执行能力；
- 写动作显示“待确认 / 已提交 / 结果未知 / 已核验成功 / 明确失败”，结果未知只显示一次检查入口；
- 刷新或路由切换后的未完成读取显示“已中断，可手动重试”，写动作不自动重放；
- 所有详情使用安全 DOM 创建，模型文本只走既有 Markdown/文本安全渲染路径。

## 7. 错误和恢复

- 事件校验失败：记录固定 `trace-invalid`，停止当前阶段，不污染后续阶段；
- 本地范围为空：显示 `scope-empty`，不调用回答模型；
- 部分读取失败：保留成功证据，记录 `read-partial`，回答中明确缺口；
- 全部读取失败：记录 `read-failed`，跳过回答阶段；
- 未知计划降级：记录 `plan-downgraded`，只读执行；
- 未知写回执：记录 `write-unknown`，只允许一次检查；
- 刷新中断：将进行中的读流程标为 `stale`/可手动重试，写流程保持未知，不自动重放。

## 8. 验收测试

1. 协议单元测试：字段白名单、非法状态迁移、数量/文本截断、敏感字段清理和固定错误码。
2. 计划兼容测试：已知变体归一、未知版本只读降级、含写动作的未知版本拒绝、意图同义词归一。
3. 副驾/研究测试：阶段与实际读取顺序一致，部分失败和空范围不虚报完成，引用只来自本地验证集合。
4. 工作台测试：四类 AI 流程显示统一时间线；折叠/展开、限制详情、会话切换和迟到响应隔离正确。
5. 写动作测试：确认、提交、明确失败、未知结果和一次性只读检查的阶段状态正确，不出现自动重试。
6. 隐私测试：本地历史和 action history 不含正文、CSRF、完整 URL、目标映射、凭据或模型隐藏推理。
7. 回归和发行测试：`npm test`、`npm run build`、`npm run verify:dist`、`git diff --check` 全部通过，LTS 排除边界不变。

## 9. 非目标

- 不展示模型隐藏推理或生成“思维链”；
- 不把事件协议变成站外遥测或云端审计服务；
- 不改变现有模型供应商、API Key 存储方式、研究预算、写动作二次确认和 M10.1 回执语义；
- 不增加未经确认的写动作或批量写入；
- 不自动恢复并重放刷新前的读取或写请求。
