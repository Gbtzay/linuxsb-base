# skin 第十四步：原生正文增强拆分

日期：2026-10-31。以第十三阶段完成后的工作区为基线，保留既有未提交改动。

## 结构与职责

新增 `native-enhancements-controller.js`，入口为 `createSkinNativeEnhancementsController({ window, document, topicUrl, startOnline })`，提供 `refresh()` 与 `clear()`。控制器集中原生评论对话树、回复父楼层记录、楼层链接规范化、折叠交互、正文验证控件准备，以及相关观察器、计时器与文档事件。

- `refresh()` 保留原顺序：重建/观察当前帖子列表、准备原生验证控件、准备 CAP 控件、观察延迟插入控件，最后调用 `startOnline()`。`topicUrl` 使用既有 SPA 文档控制器的规则，不复制路由判断。
- `clear()` 依次清理对话树观察器及计时器、解绑文档回复生命周期监听、提升验证代次并清理其观察器和计时器，对应原拆壳代码的三次调用。
- 九项状态（线程观察器、列表、计时器、事件绑定标记、表单父楼层 WeakMap、验证观察器、计时器、代次、任务 WeakMap）统一移入控制器，模板不保留副本。

构造发生在文档控制器之后、SPA 事务控制器之前，只保存依赖和状态。模板保留真实节点存档、楼层滚动定位、渲染和全局事件编排，通过 `refreshNativeRouteEnhancements` / `clearNativeRouteEnhancements` 方法别名接入原调用位置。

## 不变约束

1. skin **2.0.49**，Oxygen/LTS **2.0.54**，Hydrogen **2.4.2**；19 个显式 skin 模块，正式 21、开发 26 个套件模块。
2. 不新增依赖、配置、持久化字段、事件或模块运行时加载器；保留原生 CAP 控件的现有动态加载和站点验证流程。
3. 保持对话树五条可见阈值、折叠/目标显露、父楼层推断、replyid 链接规范化、原节点顺序和事件语义；保留验证任务的让出执行、代次与连接状态检查。
4. 保持已有 DOM 标记与节点上的交互监听策略，不扩大为原生 DOM 还原或验证功能变更。`clear()` 仅合并原有三项清理调用，先后顺序不变。
5. 前十八模块、Hydrogen 源码和两份产物保持不变；UTF-8 无 BOM、LF；在当前分支保留全部既有改动，不提交或推送。
