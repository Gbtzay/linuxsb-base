# AI 站内操作代理设计方案

**日期：** 2026-09-30  
**状态：** 已确认设计，等待用户审阅规格  
**关联模块：** `ai-workbench`、`ai-copilot`、基座 `src/core.js` / `src/ui.js`、站点动作提供方

## 目标

让 AI 工作台像 Copilot 或浏览器侧边栏助手一样理解自然语言，并在 linux.sb 站内完成一组可解释、可回放、可测试的只读操作。

首版覆盖：

- 导航到首页、版块、帖子、用户页和已登记功能页；
- 站内搜索；
- 应用已登记的列表筛选；
- 打开基座或插件面板。

首版不执行回复、点赞、收藏、签到、发帖或其它改变站点状态的动作。未来写操作沿用同一协议，但必须单独声明 `write` 权限并重新设计确认流程。

## 已确认的产品边界

- AI 只读：不申请 `write`、外部 `net` 或 `admin` 权限；站内搜索只走基座提供的 `read` 语义 API。
- 命令先生成计划，用户查看计划后点击一次“执行计划”。
- 计划中的每个动作都来自本地注册表；模型不能直接输出 DOM 选择器、JavaScript、任意 HTTP 请求或外部 URL。
- 动作按顺序执行；某一步失败即停止后续步骤，用户可以只重试失败步骤。
- 路由或页面上下文变化会让计划过期，旧计划不能操作新页面。
- 默认只发送完成命令所需的最小上下文；只有用户明确要求基于当前帖子时才采集帖子材料。
- 计划、执行状态和错误原因保存在本地；不保存 API Key，也不默认上传完整页面正文或执行历史。

## 总体架构

```text
┌────────────────────────────────────────────────────────────┐
│ AI 工作台（右栏）                                          │
│  命令输入 → 计划预览 → 用户执行 → 步骤状态 / 结果          │
└─────────────────────────────┬──────────────────────────────┘
                              │ 只调用本地动作执行器
┌─────────────────────────────▼──────────────────────────────┐
│ 基座 AI Action Registry                                     │
│ 目录、schema、页面过滤、权限门、计划校验、生命周期注销      │
└─────────────┬───────────────────┬──────────────────────────┘
              │                   │
      ┌───────▼───────┐   ┌───────▼────────┐
      │ 站点动作提供方 │   │ UI / 插件动作   │
      │ navigate/search │   │ filter/openPanel│
      └───────────────┘   └────────────────┘
```

职责边界：

- **基座**保存注册表并执行通用校验，不理解 AI 业务文案。
- **动作提供方**登记一个稳定动作及其参数、页面条件、预览文案和执行函数。
- **ai-copilot**负责复用现有模型配置，生成严格 JSON 计划，并返回模型阶段信息。
- **ai-workbench**负责命令输入、计划卡片、执行状态和结果展示，不访问调试 RPC，不直接读写任意 DOM；因为会保存本地计划历史，manifest 增加 `storage` 权限。
- **skin**继续只负责右栏宿主和视图切换。

## 动作注册协议

基座增加 `api.ai.registerAction()` 和 `api.ai.actions(context)`。注册函数返回注销函数，由插件生命周期自动调用。

```js
api.ai.registerAction({
  id: 'site.search',
  version: 1,
  label: '站内搜索',
  description: '按关键词和字段搜索站内内容',
  permission: 'read',
  pages: ['home', 'forum', 'topic', 'user'],
  args: {
    query: { type: 'string', minLength: 1, maxLength: 120 },
    field: { type: 'enum', values: ['全文', '标题', '用户'] },
  },
  preview: (args) => `搜索“${args.query}”，字段：${args.field}`,
  execute: async (args, context) => ({
    kind: 'navigation',
    url: `/search?q=${encodeURIComponent(args.query)}`,
    label: '已打开搜索结果',
  }),
})
```

### 注册记录字段

| 字段 | 要求 |
|---|---|
| `id` | 稳定、命名空间化，如 `site.search`、`ui.openPanel` |
| `version` | 正整数；参数语义改变时递增 |
| `label` / `description` | 给用户和模型看的短文案，不包含动态敏感数据 |
| `permission` | 首版只能是 `read`；基座校验提供方是否声明该权限 |
| `pages` | 可选页面类型白名单；未匹配时不进入当前动作目录 |
| `args` | 严格 schema；默认拒绝未知字段和额外属性 |
| `preview(args, context)` | 纯函数，生成用户可读的执行说明，不产生副作用 |
| `execute(args, context)` | 只执行登记过的本地行为，返回可序列化结果 |

动作注册表还提供：

- `available(context)`：过滤页面不适用、插件停用或上下文缺失的动作；
- `describe()`：输出给模型的最小目录，只含动作 ID、用途、参数约束和页面条件；
- `validate(step, context)`：返回结构化错误码，不执行副作用；
- `dispose(owner)`：插件停用后移除动作和正在等待的执行引用。

## 首批动作

### `site.navigate`

打开站内已登记目标：`home`、`forum`、`topic`、`user`、`feature`。目标 ID 必须是数字或动作目录中的固定键；路径由本地路由构造，模型不能传入任意 URL。

### `site.search`

参数为关键词、字段和可选排序。关键词限制长度和控制字符；工作台调用基座新增的受限 `api.net.search(query, field)` 语义 API。linux.sb 当前搜索协议是 `POST /search` 后取得站内 redirect，传输层虽然是 POST，但该专用 API 只允许固定搜索字段和固定站内端点，不接受任意方法、路径或请求体，因此按“只读搜索能力”暴露。现有通用 `api.actions.search` 仍保持 `write` 权限门，不允许工作台通过它绕过权限模型。

### `site.filter`

只应用提供方声明的筛选项，例如当前列表的作者、未读、状态或排序。筛选值来自枚举目录，不接受 CSS 选择器或任意表达式。

### `ui.openPanel`

只打开基座和已注册插件面板。面板 ID 由本地注册表生成，模型只能选择目录中的 ID。

## 模型计划协议

模型只能返回以下版本化结构：

```json
{
  "version": 1,
  "summary": "打开程序版块并搜索缓存",
  "steps": [
    {
      "action": "site.navigate",
      "args": { "target": "forum", "id": 9 }
    },
    {
      "action": "site.search",
      "args": { "query": "缓存", "field": "标题" }
    }
  ]
}
```

协议规则：

- `version` 必须为支持的计划版本；
- `steps` 至少 1 步、最多 5 步；
- `action` 必须存在于当前本地目录；
- `args` 通过动作 schema 严格校验；
- 未知顶层字段、未知步骤字段、未知动作和外部 URL 一律拒绝；
- `summary` 和错误文案只作为展示文本，不作为执行指令；
- 计划校验在本地完成，模型声称的“已执行”不可信，只有执行器结果才改变状态。

计划状态：`draft` → `ready` → `running` → `completed`；异常状态为 `partial`、`failed`、`expired`、`cancelled`。

## 右栏交互

AI 工作台保持现有三个段落：操作台、当前帖子、追踪。命令模式作为操作台内的一个子模式，与现有自然语言查询并列，默认不改变原有查询入口。

### 计划预览

用户输入命令后，右栏显示：

- AI 对命令的简短理解；
- 每一步的动作名称、目标、参数和预览文案；
- 本次会发送给模型的上下文摘要；
- “执行计划”“重新生成”“取消”按钮。

预览阶段不调用动作 `execute`，也不触发站内导航或筛选。

### 执行状态

点击执行后，每一步显示：`待执行`、`执行中`、`已完成`、`已跳过` 或 `失败`。结果只显示动作返回的可读摘要和站内链接，不把执行器内部对象直接渲染为 HTML。

导航动作造成 `route:changed` 时，执行器等待新页面就绪，再对剩余步骤重新校验；上下文不匹配则将计划标为 `expired`。

### 异常恢复

- 意图不明确：展示候选解释，不创建可执行计划；
- 参数不合法：指出字段和允许值，回到输入编辑；
- 页面不适用：说明需要的页面类型，提供导航建议；
- 单步失败：停止后续步骤，保留已完成步骤，提供“仅重试失败步骤”；
- 路由或插件停用：使计划过期，丢弃旧回调；
- 模型不可用：仍可从动作目录手动选择已登记动作。

## 上下文和隐私

默认上下文结构：

```js
{
  route: { type, url, id },
  page: { title, forum },
  selection: null,
  availableActions: ['site.navigate', 'site.search', 'site.filter', 'ui.openPanel'],
  visibleState: { search: false, activeFilter: null },
}
```

不发送 API Key、Cookie、CSRF、未请求的私信、配置、回复表单和完整 DOM。用户明确要求“根据这篇帖子”时，才按 AI 副驾现有的字符预算采集帖子内容；工作台显示本次发送内容供展开查看。

计划、步骤状态、错误原因和用户命令默认保存在工作台自己的本地存储命名空间。模型响应不能写入站点表单，也不能改变追踪状态。

## 权限和安全

- `ai-workbench` 首版使用 `read`、`storage`、`ui`、`events`；不增加 `write`、外部 `net` 或 `admin` 权限。
- 只有动作提供方声明的权限能进入执行器；工作台不继承提供方的额外权限。
- 站内路径通过基座站点路由构造，拒绝协议相对 URL、外部 URL、脚本协议和任意查询参数。
- 计划最多 5 步，单个字符串和数组有长度上限；执行器串行执行，不允许模型自行并发。
- 任何动作都必须返回可序列化结果；结果不得包含密钥、Cookie、CSRF 或完整私密页面内容。
- 未来写动作必须声明 `write`，执行前展示目标、内容和影响范围并逐项确认；首版不实现写动作和批量写操作。

## 测试验收

### 基座和动作注册表

- 注册、排序、页面过滤、重复 ID、注销和插件停用清理；
- schema 拒绝未知字段、越界值、外部 URL、任意选择器和脚本；
- 权限不满足时动作无法注册或执行；
- 语义搜索只能通过固定的只读搜索 API，通用 `api.actions.search` 仍受 `write` 门保护；
- 执行结果必须是可序列化值。

### 工作台和执行器

- 计划预览不触发动作；
- 一键执行按顺序调用动作并显示状态；
- 未知动作、过期路由、页面不适用、部分失败和单步重试；
- 路由切换或插件停用后旧计划不能回写；
- 模型不可用时手动动作目录仍可用；
- 首版工作台不申请或调用 `write`、外部 `net`、`admin`；本地计划历史只使用 `storage` 命名空间，站内搜索只调用基座的 `read` 语义 API。

### 产物和回归

- Oxygen 收录动作提供方和工作台；
- LTS 不收录 AI 工作台和未来动作代理；
- `npm run build`、`npm run verify:dist`、`npm test` 全部通过；
- 保留 linux.sb BBS1ORG v99.0 与 bbs1.org v10.3 的帖子/右栏 DOM 回归样本。

## 分阶段交付

### A1：只读动作闭环

实现基座动作注册协议、四个首批动作、命令计划预览、串行执行、错误恢复和测试。

### A2：页面内只读扩展

增加楼层定位、展开/折叠、只看某用户、复制证据等动作；每个动作仍由插件登记并声明页面条件。

### A3：写动作设计评审

单独评审回复、点赞、收藏、签到等动作的权限、逐项确认、幂等性、撤销提示和审计记录。A3 不自动继承 A1 的执行资格。

## 自检结论

- 本规格只覆盖首版只读动作代理，写操作被明确拆到后续阶段；
- 模型不能绕过本地动作注册表或权限门；
- 计划预览、执行状态、路由失效和失败恢复均有明确状态与测试要求；
- 没有依赖任意 DOM 点击或外部 URL 的模糊步骤。
