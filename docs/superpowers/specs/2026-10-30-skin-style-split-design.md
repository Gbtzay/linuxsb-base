# skin 分步拆分：第二步样式生成

承接第一步状态模块，提取 `shellCss`、`canvasCss` 与正文样式组合逻辑，使样式可直接测试且继续进入独立脚本、开发/正式 Oxygen 与 LTS。

## 模块与边界

- 新增 `plugins/skin/styles.js`，包含固定字体栈、`shellCss()`、`canvasCss()` 和 `skinCss(cfg = {}, { shellActive = false, uiMode = 'legacy' } = {})`。只生成 CSS 字符串，不读取 DOM、视口、存储或全局可变配置，不缓存结果。
- `cfg` 只消费 `typography`、`density`、`codeblock`、`floors`、`measure`。实际壳启用状态与界面模式由调用方传入；旧三段式窄屏回退仍由模板的 `shellUiActive()` 判定。
- 字体栈随样式模块迁移；外观覆盖继续通过既有 CSS 变量及 `applyShellTokens()` 生效。DOM 状态类、style 节点创建、配置变更、媒体生命周期、导航和清理均留在模板。
- 模板通过唯一的 `// @LSB_SKIN_STYLES` 标记注入样式模块；`restyle()` 传入当次配置和界面状态，避免捕获旧配置。
- 生成器维护状态、样式两个显式模块。每个输入单独校验 BOM、CRLF、AI 标记；两个注入点各自必须唯一，错误语法或缺失文件必须失败。组合后继续执行现有分发裁剪。

## 约束与验收

- 保留当前工作区已有改动，不创建提交或推送；UTF-8 无 BOM、LF；不新增依赖。
- skin 2.0.37，Oxygen/LTS 2.0.42；Hydrogen 2.4.2，正式 21 / 开发 26 个模块。
- CSS 规则、顺序、媒体查询和界面行为不变；只允许因提取产生行首缩进差异。提取前捕获 CSS 输出，逐项比较 128 组配置/模式/启用组合。
- 构建夹具修改样式源后，独立脚本和 dev/release 套件的实际运行结果随之改变；只读校验能拒绝样式源或输出漂移。
- 纯函数测试覆盖界面选择、独立配置开关和配置更新；现有双界面、窄屏、减少动效、软跳与阅读中心验收全部保留。
- 按顺序运行开发/正式构建、分发校验、零跳过校验、完整 Node 回归与浏览器冒烟。保存本轮证据，不复用上一轮通过数量。
