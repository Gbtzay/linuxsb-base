# 插件功能菜单设计

## 目标

在新版氢壳底部三点工具菜单中恢复旧侧栏的五个插件功能入口，并提供这些功能对应的设置入口，以及一个可浏览全部插件设置的目录。

## 用户范围确认

旧侧栏的五个功能入口是：AI 历史、签到日历、积分趋势、称号行情、年度报告。用户确认采用“恢复这五个入口，另加全部插件设置目录”的范围。

## 交互设计

1. 底部胶囊中的三点按钮仍打开现有“工具”面板；其中新增“插件功能”入口。
2. 点击“插件功能”后打开独立的液态玻璃面板，标题为“插件功能”。面板分为“功能入口”和“插件设置”两个区域。
3. “功能入口”区域恢复旧侧栏的五项功能。只显示所属插件当前处于 active 状态且目标面板或动作可用的项目。主按钮继续调用已有插件面板或动作，不复制插件功能逻辑。
4. 功能条目只有在插件自身设置页确实存在时才显示齿轮按钮。齿轮打开所属插件的设置页；没有设置页的插件不显示无效齿轮。
5. “插件设置”区域提供“全部插件设置”目录入口。目录列出已注册且有设置页的插件，包括已停用插件；点击条目打开该插件设置页。没有设置页的插件不进入目录。
6. 面板沿用现有玻璃表面、关闭按钮、Escape 关闭、焦点管理和窄屏滚动规则。打开插件设置前关闭氢壳面板，避免设置面板与壳面板叠压。
7. 现有 AI 助理仍留在底部胶囊；AI 操作台不加入插件功能列表，避免恢复已删除的重复入口。

## 入口与数据来源

- `skin.user.js` 现有 `collectTools()` 是五个旧功能入口的数据来源，保留现有面板 ID 与 `title-quotes:open` 动作。
- 插件名称和状态从只读插件目录读取；功能入口可用性从插件状态、已注册面板目录或 RPC 处理器校验。
- 基座新增 `api.ui.settingsPlugins()` 与 `api.ui.openPluginSettings(pluginId)`：前者只返回声明了 `config` schema 的插件 ID、名称和状态，不暴露 schema；后者按插件 ID 打开独立设置表单，保留插件通过 `configTab` 注册的附加设置内容，不依赖可能被功能页占用的分页 ID。
- 插件设置目录通过 `settingsPlugins()` 列出可配置插件，包括已停用或因页面条件跳过的插件；功能条目齿轮使用 `openPluginSettings()`。
- 页面内容每次打开面板时重新读取；插件启用或停用变化不会留下过期入口。

## 空状态与失败处理

- 若五个插件功能均不可用，功能区显示简洁空状态，不显示空白按钮。
- 若当前插件状态在点击前发生变化，重新校验目标；目标不可用时关闭面板并显示现有 toast 提示，不执行无效 RPC。
- 设置页只有在目录中确认存在时才可点击，避免未知 ID 被设置面板回退到首个标签。

## 不在范围内

- 不修改插件自身的功能、设置 schema 或存储格式。
- 不改变插件启停、依赖解析和旧侧栏布局。
- 不把所有插件动作自动猜测并塞进菜单；目前只恢复已经存在且用户确认的五项。
- 不增加 AI 操作台入口。

## 验收条件

- 三点工具面板显示“插件功能”，AI 助理快捷入口保持原样。
- 插件功能面板恢复五个既有功能，并且每项仍触发原来的面板或插件动作。
- 有对应设置页的旧功能显示直接设置入口；没有设置页的项目不显示无效齿轮。
- “全部插件设置”只列出确实有设置页的插件，并包含已停用但仍可配置的插件。
- 切换插件启用状态后重新打开菜单，入口状态与插件目录一致。
- 桌面和窄屏布局可用，面板关闭与键盘焦点行为和现有壳面板一致。
- AI 操作台不重新出现。

## 实现边界

需要扩展 `plugins/skin.user.js` 中的工具面板与壳内面板交互；由于已有 `api.ui.panels()` 无法区分同 ID 的功能页和自动设置页，基座还需在 `src/core.js` 与 `src/ui.js` 中增加受 `ui` 权限保护的设置插件目录和独立设置表单入口。相应回归测试覆盖 `test/core.test.js` 与 `test/skin-canvas.test.js`；完成后运行现有构建与浏览器冒烟检查。实现遵循测试先行。
