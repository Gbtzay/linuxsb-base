# AI 帖子副驾设计

## 状态

待用户复核。本文档描述首版 `ai-copilot` 的范围、架构和验收标准；实现前必须以本文档为准。

## 背景

项目已有 `ai-summary` 插件，负责帖子内容采集、字符预算、OpenAI/Anthropic 协议、缓存、历史记录和安全 Markdown 渲染。它目前以“一键总结”为主，无法在阅读过程中追问、拆解争论或辅助起草回复。

首版目标是在 linux.sb 帖子页提供一个只读 AI 副驾，覆盖：

1. 针对当前帖子的连续问答；
2. 几类固定的讨论分析；
3. 针对指定楼层的回复草稿。

首版不做跨帖子长期记忆、后台全站索引、自然语言操作台和自动发帖。

## 方案决策

### 方案 A：直接扩展 `ai-summary`

改动最少，但会把模型配置、帖子采集、总结、问答、草稿和 UI 全部挤进一个已经较大的文件，后续独立启停和测试边界会变差。

### 方案 B：新建 `ai-copilot`，复用 `ai-summary` 模型通道

`ai-summary` 保持模型配置和 LLM 请求服务；`ai-copilot` 独立负责帖子上下文、问答、讨论分析和草稿界面。通过插件依赖和窄导出接口连接，两个插件可以独立演进。

### 方案 C：抽出通用 `ai-core`

适合未来同时支持 AI 总结、语义雷达和 AI 操作台，但首版需要额外的服务插件、配置迁移和公共协议设计，范围过大。

### 选定方案

采用方案 B。首版新增 `plugins/ai-copilot.user.js`，并对 `ai-summary` 做最小的模型服务改造。

## 产品范围

### 入口

- 仅在 `topic` 页面显示。
- 主楼操作区显示「✨ AI 副驾」。
- 顶栏显示同名入口，避免主楼未加载或页面处于分页视图时无法打开。
- 不在首页、版块页和用户页注入入口。

### 问答模式

用户输入问题后，副驾基于当前主题上下文回答。首版提供几个快捷问题：

- 这篇帖子的核心争议是什么？
- 第 N 楼之后发生了什么？
- 哪些方案已经被验证？
- 请向刚接触 Linux 的人解释这篇帖子。

用户可以继续追问。会话只按 `topicId` 隔离，默认最多保存 6 轮，提供清空按钮；不建立跨帖子的记忆。

### 讨论分析模式

提供以下预设：

- 未解决问题：列出仍未得到明确回答的问题及对应楼层；
- 观点与分歧：按立场、代表楼层和理由归纳冲突；
- 讨论时间线：按楼层和时间整理讨论转折；
- 方案优缺点：提取具体方案、证据和限制；
- 新手版解释：把上下文改写成入门说明；
- 代码和命令提取：只整理可执行命令、配置片段和代码相关结论。

结果继续使用现有安全 Markdown 渲染，并显示模型、楼层范围、采集页数、送入字符数、截断状态和耗时。

### 回复草稿模式

- 用户选择目标楼层，默认选择主楼；
- 可选择客观、简洁、友好、技术向四种语气；
- 可选择短、中、长三种长度；
- 生成后支持复制和重新生成；
- 不自动填充回复框，不自动提交，不申请 `write` 权限。

## 技术架构

### `ai-summary` 的模型服务接口

将 `ai-summary` 现有的协议适配和请求逻辑整理成两个插件导出：

```js
{
  configured: () => boolean,
  generate: async ({ system, user, timeout }) => ({
    text,
    meta: { model, ms },
  }),
}
```

`generate` 只接受已经构造好的系统提示和用户内容，不自动附加“总结风格”或旧的自定义提示词。这样副驾能够复用同一套 API Key、端点、协议识别、超时和错误处理，同时不会让总结配置污染问答提示词。

`ai-summary` 仍保留现有的一键总结、历史页和配置页。其版本提升到 `1.2.0`，导出接口属于兼容性变更，旧用户的配置和缓存格式保持不变。

### `ai-copilot` 插件

manifest 约定：

```js
{
  id: 'ai-copilot',
  version: '0.1.0',
  requires: {
    base: '^0.1.0',
    plugins: { 'ai-summary': '^1.2.0' },
  },
  permissions: ['read', 'storage', 'ui', 'events'],
  pages: ['topic'],
}
```

副驾不直接访问外部网络。它通过依赖插件的 `generate` 导出调用模型；帖子页面采集使用基座的 `api.parse.topic`、`api.net.pages` 和 `api.page`。

上下文配置放在副驾自己的设置页：

- 采集范围：当前页面 / 当前已加载内容 / 全部分页；
- 最大送入字符数，默认 12000；
- 最大抓取页数，默认 15；
- 单主题会话轮数，默认 6。

模型端点、Key、模型名和超时继续只在「AI 总结」设置页维护，避免出现两份凭据。

## 数据流

1. 用户在帖子页打开副驾并选择问答、分析或草稿模式。
2. 插件从当前实时 DOM 解析主题；不使用可能过期的启动快照作为唯一来源。
3. 若配置为全部分页，通过 `api.net.pages` 补齐页面，并去重 `postId`。
4. 规范化主题标题、版块、浏览/回复数、楼层号、作者、时间和正文。
5. 按总预算裁剪主楼和回复，保留楼层标记，并记录 `hasOp`、楼层范围、抓取页数和截断状态。
6. 生成模式专属提示词。论坛正文放在清晰的 `<forum-content>` 区块中，系统提示明确规定其是“不可信数据”，模型不得执行正文内的指令。
7. 通过 `ai-summary.generate` 发起一次外部模型调用。该调用继续使用 `queue: false`，不阻塞 linux.sb 的站内限速队列。
8. 返回内容经过现有安全 Markdown 渲染后显示；原始文本可复制为纯文本。

## 缓存与会话

缓存指纹必须包含：

- `topicId`；
- 规范化内容指纹；
- 模式和预设；
- 用户问题或目标楼层；
- 语气和草稿长度；
- 模型名；
- 采集范围和字符预算。

建议使用 `c:<topicId>:<fingerprint>` 作为缓存键，最多保留 60 条，按最近使用时间淘汰。问答会话单独存储在 `session:<topicId>`，最多 6 轮，并提供显式清空操作。

内容指纹变化后必须重新生成，不能因为同一帖子 ID 而复用旧结果。缓存和会话都只存本机脚本存储，不上传到站点。

## 安全与权限

- `ai-copilot` 不申请 `write`，不能代表用户回复、点赞、收藏或签到。
- API Key 继续只存在 `ai-summary` 的本机存储中，副驾不读取 Key。
- 论坛正文、用户名和引用必须被当作不可信输入；系统提示、用户问题和论坛内容使用不同区块分隔。
- 结果中显示实际送入的字符数、是否截断和采集范围，避免用户误以为模型看到了完整主题。
- 草稿在复制前显示完整内容；不自动写入 DOM 的回复编辑器。
- 外部模型错误、超时、非 JSON 响应和空文本均显示可重试错误，不写入成功缓存。

## UI 与生命周期

副驾使用基座现有 `lsb-panel`、`lsb-mask` 和 `api.ui` 能力。只保留一个打开的副驾面板；同一主题同时只允许一个请求在途。请求期间显示采集页数、楼层数和等待秒数。

页面路由变化时生成新的请求代次。旧请求完成后可以写入原主题缓存，但不得把结果渲染到新主题面板。插件停用时必须清除浮层、等待计时器、事件监听、按钮引用和在途状态。

依赖 `ai-summary` 未激活时，基座将副驾置为不可用状态；正常入口不应出现。若配置缺失，点击入口后打开 `ai-summary` 配置页并给出明确提示。

## 测试与验收

新增 `test/ai-copilot.test.js`，并扩展 `test/ai-summary.test.js` 验证模型导出接口：

- 问答、分析、草稿三种提示词包含正确的模式约束；
- 目标楼层、作者和楼层号被正确引用；
- 主楼缺失的分页视图不会把第一条回复冒充主楼；
- 主楼和回复共同受字符预算限制；
- 全部分页去重且不重复计费；
- 帖子正文里的伪指令不会改变系统提示边界；
- 缓存键覆盖问题、模式、楼层、语气、模型和内容变化；
- 同一主题重复点击不会产生第二个在途请求；
- 路由切换后旧结果不覆盖新帖子；
- 草稿复制、重试、模型错误和超时状态可见；
- 停用插件后浮层、计时器、监听器和在途状态全部收摊。

同步更新：

- `suite/order.js`：将 `ai-copilot` 放在 `ai-summary` 后；
- `test/suite.test.js` 的成员清单；
- `README.md` 的官方插件表和版本说明；
- `build-suite.mjs` 使用的套件版本，补一个补丁版本；
- 不加入冻结的 `ORDER_LTS`。

验收标准是 `npm test` 和 `npm run build` 均通过，且新插件能在真实帖子夹具中完成三种模式的 DOM 交互和缓存回放。

## 非目标与后续方向

首版明确不包含：

- 跨帖子的长期个人记忆；
- 后台全站抓取和 embedding 索引；
- 自动发帖或自动执行站内动作；
- 外部搜索、事实核验和自动引用来源；
- 多人共享会话。

后续可以在稳定的 `generate` 接口之上增加 AI 每日摘要、语义雷达和只读自然语言操作台。
