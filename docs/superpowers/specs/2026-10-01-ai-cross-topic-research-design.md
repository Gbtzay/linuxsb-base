# AI 工作台跨主题资料检索设计

**日期：** 2026-10-01

**状态：** 用户已确认设计，待审阅规格文档
**涉及模块：** `ai-workbench`、`ai-copilot`、站点解析层与只读站内搜索接口

## 1. 目标

让 AI 工作台能从站内搜索、本人发布的主题和本人收藏中发现候选主题；由用户选择主题后，再读取有限正文并生成带本地证据引用的回答。

首版先交付跨主题搜索与选读，再接入本人主题和收藏。两者共用候选、选择、主题读取、字符预算和引用流程。

## 2. 已确认的交互决策

- 用户提出跨主题问题后，计划器按问题选择标题、正文或回帖中的一个搜索字段，并在结果区显示字段名。
- 用户可主动切换搜索字段扩大候选；结果按主题 ID 合并，保留来源字段标记。
- AI 先显示站内搜索候选。用户勾选主题后，最多选择 3 篇，再点击读取。
- 正文读取按钮明确说明所选内容会发送给当前配置的 AI。
- 每个选中主题仅读取第一页的楼层内容。所有主题共用现有 `CONSOLE_MAX_CHARS` 预算（18,000 字符）。
- 搜索结果页和个人列表页均只在用户手动操作后继续读取下一页；不自动翻页或遍历整个站点/账号。
- 本人数据仅在用户明确提到“我的”或主动选择个人数据源时读取。个人来源限于本人发布的主题和本人收藏的主题；回帖不在首版范围内。
- 本人身份从当前本地登录状态读取。模型不能提交用户 ID；身份不可用时停止个人数据读取并说明原因。
- 跨主题搜索命中只负责发现候选。正文分析只使用用户选中主题的第一页；如果匹配内容在后续页，回答不得声称读取了该内容。

## 3. 数据源与候选发现

### 3.1 站内搜索

复用基座固定的站内搜索接口。搜索请求由用户的跨主题问题触发，计划器输出受限的搜索词和一个字段：`title`、`body` 或 `reply`。本地校验字段、搜索词长度和字符，再调用同源搜索接口；只接受已知的站内搜索结果路由。

候选发现只解析搜索当前结果页。候选最多保留 40 条，并使用白名单字段：主题 ID、标题、作者名称、版块名称、回复数、最后活跃时间及搜索来源字段。原始 HTML、用户 ID 和原始 URL 不进入模型上下文。

候选列表可手动加载下一页。切换字段或加载下一页都由用户显式触发；每次操作只读取请求的那一页，不在后台自动扩展。

### 3.2 本人主题与收藏

个人来源有两个本地枚举值：`my-topics` 和 `my-favorites`。本地逻辑仅在用户请求或工作台来源选择允许时读取对应来源，并使用本地 `api.me` 身份构造用户页路由。

每个来源首次读取第一页；“加载下一页”按钮每次只读取一个后续页。本人主题与收藏中同一主题按正整数主题 ID 去重，候选保留“本人发布”“本人收藏”来源标签。用户无法登录、缺少本地身份或页面解析失败时，停止读取该来源，不退回到其它用户或推测身份。

### 3.3 候选卡片

候选列表由工作台本地渲染，显示标题、版块、作者、回复数、活跃时间和来源。主题链接由本地主题 ID 生成。候选元信息用于帮助用户选择，不作为未选主题的正文证据发送给回答模型。

## 4. 选中主题与读取正文

用户只能选择当前候选集合中本地验证过的主题 ID，且最多选择 3 篇。模型给出的任意主题 ID、链接或 URL 不能加入候选集合。

点击读取后，本地仅对选中 ID 使用固定主题路由读取每篇第一页，并用现有主题解析器提取楼层白名单字段。多个主题共同受 `CONSOLE_MAX_CHARS` 约束；应为选中主题公平分配预算，并允许小主题未用完的预算供后续主题使用。超预算时标明截断状态。

没有选中主题时，不请求主题正文，也不调用回答模型。某个主题读取失败时，显示该主题的失败状态；成功读取的主题可继续回答，并在回答范围中明确标注部分结果。全部读取失败时跳过回答模型。

## 5. 计划、引用与历史

### 5.1 受限计划

跨主题检索使用新版本的受限查询计划协议，包含有限的搜索来源、搜索词和字段。个人来源由本地用户请求/来源选择单独授权，计划器不能仅凭自身输出开启个人数据读取。计划中不接受任意 URL、HTTP 请求参数或用户 ID。

本地校验负责确认：

- 站内搜索字段属于 `title`、`body`、`reply`。
- 搜索词满足长度和字符规则。
- 个人来源明确由用户触发，并使用本地登录 ID。
- 候选主题 ID 来自当前已加载的本地解析结果。
- 正文读取数不超过 3，且路由始终由本地白名单生成。

### 5.2 回答与证据

仅用户选中的主题第一页正文可以进入回答模型。主题列表候选和未选主题正文不进入回答请求。

回答引用只能映射到本次实际读取的主题和楼层；引用链接由本地路由生成，未知主题或楼层不生成链接。以回帖字段搜索时，后续分页的命中不能被当成已读取证据。

### 5.3 本地历史

候选页面、抓取的主题正文和原始 URL 不持久化。工作台沿用当前会话历史规则，只保存用户问题、回答、阶段摘要和经本地验证的引用 ID。刷新后未完成的请求保持可手动重试，不自动重放搜索、抓取或写操作。

## 6. 模块职责

- `ai-workbench`：呈现候选卡片、搜索字段/来源状态、勾选、继续加载和读取确认；管理请求代次及历史 UI。
- `ai-copilot`：生成并验证计划，调用受限搜索/读取接口，应用字符预算，准备回答上下文，映射和验证引用。
- 站点适配层：负责搜索列表、用户主题/收藏列表和主题楼层 DOM 的解析；原始选择器不散落到 AI 插件中。
- 基座 `api.net.search` / `api.net.doc`：仅执行同源、已知路由的只读请求；搜索重定向继续经过现有路径校验。
- `ai-actions` 与 `ai-write-actions`：维持既有职责。此次资料检索不改变它们的动作权限或写入确认流程。

首版在 `ai-copilot` 内增加受限资料源适配器，并由工作台消费其候选和读取结果。暂不新增独立插件；当资料源、权限或生命周期需要独立演进时，再评估拆分 `ai-research` 插件。

## 7. 错误与边界

- 非法计划、字段、搜索词、外部/未知重定向或不在本地候选集合中的 ID：本地拒绝，不发出正文读取请求。
- 搜索无结果：显示无候选状态，不请求主题正文。
- 个人来源缺少登录身份：显示需登录/身份不可用状态，不发出个人页请求。
- 读取失败或部分成功：按主题显示状态，答案只根据成功读取的楼层生成。
- 用户切换会话或路由后，迟到的搜索/读取结果不得覆盖新会话；刷新后不自动重新请求。
- 所有本地页面和主题读取都不自动翻页。下一页请求只由用户操作触发。

## 8. 验收标准

- 跨主题问题能生成受限搜索词与单个字段；字段显示在候选区，用户可手动扩大到其它字段。
- 搜索结果只读取当前结果页；用户可以显式继续加载候选页；候选按主题 ID 去重。
- 搜索候选显示主题元信息并提供安全的站内主题链接；任何候选正文都不会在用户选择前进入回答模型。
- 个人主题/收藏仅由明确个人请求或来源选择触发，身份仅取自本地登录状态；首屏读取并支持手动加载后续页。
- 用户最多选择 3 篇；每篇只读取第一页；总正文预算不超过 18,000 字符并显示截断/部分失败状态。
- 无效计划、任意 URL、外部重定向、模型自报 ID、未选主题 ID 均不能触发正文请求或伪造引用。
- 引用只映射到所选且实际读取的主题/楼层；后续页未读取的搜索命中不会被描述成已验证证据。
- 候选和正文不写入本地对话历史；刷新恢复不自动重放网络或写入操作。
- 现有当前页列表查询、帖子副驾、追踪、站内动作和 LTS 排除规则不回归。
- 测试覆盖搜索来源与字段、候选与手动分页、个人数据触发/身份边界、选择后读取上限、预算、错误隔离、缓存和引用；完整测试、发行构建与 `verify:dist` 通过。
