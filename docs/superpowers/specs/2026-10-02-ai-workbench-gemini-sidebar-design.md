# M15：Gemini 式 AI 工作台侧栏重构设计

日期：2026-10-02

状态：设计已确认，等待生成实施计划

## 背景

AI 工作台已经具备连续对话、停止生成、流式回答、有限历史、上下文压缩、引用复核和站内写操作确认。当前界面仍沿用“工作台表单”的结构：顶部上下文提示、消息流、固定输入框、Smart 能力菜单和会话菜单彼此独立，菜单定位也曾与输入框发生重叠。

本轮参考 Chrome 侧栏 Gemini 的空状态和输入卡，把工作台收敛成一个完整的深色侧栏。界面重构只改变呈现和本地意图路由，不改变 M12–M14 的请求取消、历史边界、证据校验、缓存失效和写操作安全链。

## 目标

1. 让工作台在空会话时呈现 Gemini 式欢迎态，在有消息时自动切换为消息态。
2. 让输入区成为一个独立的底部悬浮卡，菜单按卡片外壳定位，避免覆盖输入卡。
3. 移除可见的 `@`、`/` 和 Smart 能力选择器，使用本地纯函数从自然语言和当前页面范围判断处理能力。
4. 允许用户明确取消当前页面材料；取消后本轮请求不携带页面正文、追踪材料或引用账本。
5. 让顶部更多、关闭、材料附加和模型入口有稳定的职责边界。
6. 保留旧对话记录和 M12–M14 业务接口，保证旧历史可以继续显示和重试。

## 非目标

- 本轮不实现语音输入、语音对话或麦克风权限。
- 本轮不实现多模型账户管理；模型标签只展示现有 provider 配置中的当前模型。
- 本轮不重新设计模型协议、流式传输、证据复核和站内写动作执行器。
- 本轮不把模型私有推理显示到时间线或消息流。
- 本轮不把对话导出、导入和端点诊断提前并入；它们排在本轮 UI 重构之后。

## 视觉和布局

### 侧栏外壳

AI 侧栏固定使用深色视觉，不跟随站点明暗主题切换。宽屏下侧栏宽度为 360–384px，并通过同一个 `--lsb-shell-aside` 变量同步站点主栏的右侧占位，避免调整 AI 宽度后内容被覆盖。窄屏继续使用现有顶栏和浮层入口。

颜色使用工作台自己的变量：近黑色主体、深蓝底部渐变、浅色文字、低对比度分隔线和高亮品牌色。渐变只用于欢迎态和输入卡周围的背景，不影响消息正文的可读性。

### 顶部栏

顶部栏高度保持紧凑，只包含：

- `⋮`：打开低频操作菜单。
- `×`：停止当前只读请求并通过 `shellAsideSelect('site')` 返回站点侧栏；对话和本地历史保留。

更多菜单提供新建对话、切换历史、清空历史和打开 AI 设置。能力选择不放在默认菜单首屏；对自然语言无法判断的边缘情况，菜单中保留一个二级“处理方式”兜底入口。

### 欢迎态

当前会话没有消息时，主体显示：

1. 居中的多色星标，使用 CSS 图形实现，不引入外部图片资源。
2. 当前用户昵称问候语；无法取得昵称时使用“你好！想聊点什么？”。
3. 三个圆角建议问题。建议内容根据当前路由和可用材料选择，例如当前帖子显示帖子分析，普通页面显示列表查询，存在活动追踪时显示追踪查询。

建议问题只把文本填入输入框并聚焦，不直接发起请求。

### 消息态

当前会话有至少一轮消息后，欢迎区和建议问题隐藏，消息列表占满内容区并独立滚动。现有用户问题、流式纯文本、完成后的安全 Markdown、引用、阶段时间线、停止提示、重试按钮、复核差异和写操作卡继续由现有渲染函数产生。

### 底部 composer

composer 是侧栏底部唯一的输入卡，结构如下：

1. 材料条：显示当前附加范围和简短数量信息，文本过长时截断；右侧 `×` 取消材料。
2. 工具行：`＋`、多行输入框、当前模型标签、发送/停止按钮。

`＋` 打开简单的材料菜单，可选择当前页面、当前帖子或活动追踪。菜单不使用 `@` 字符，也不呈现选项卡。当前路由不支持的材料置灰并说明原因。

取消材料后，材料条隐藏或显示“未附加页面材料”的轻提示；本轮只发送问题文本，不能读取当前页面、帖子正文、追踪项或引用账本。再次通过 `＋` 附加材料后，只更新提示和范围，不自动发送请求。

模型标签读取 `copilot.providerState().model`，没有配置时显示“配置模型”；点击后打开已有 AI 设置页。发送按钮空闲时显示发送图标，生成中复用同一位置显示停止图标；没有不可用的语音按钮。

所有菜单都放在 composer 外壳中，以外壳的实际高度计算 `bottom`，不使用固定像素抵消输入框高度。

## 状态和数据流

### 工作台视图状态

工作台在现有 `state` 上增加仅内存字段：

```text
viewMode: 'welcome' | 'messages'
openMenu: 'more' | 'materials' | 'capability-fallback' | ''
materialMode: 'attached' | 'detached'
intent: { capability, confidence, source, reason }
```

`materialMode` 默认是 `attached`，刷新或重新打开工作台时根据当前路由重新建立，不把旧页面材料自动恢复到新页面。`viewMode` 和菜单状态不写入本地历史。

### 材料取消和范围隔离

`detached` 请求只保留用户问题和必要的协议字段，不生成当前页面引用，也不向模型发送页面正文、主题列表、活动追踪、帖子 ID、楼层或原始 URL。请求缓存指纹、对话范围和压缩指纹都包含 `materialMode`，因此带材料与无材料的回答不会互相命中。

为了避免无材料追问借用上一轮的证据，`detached` 轮次使用独立范围；它只携带同一无材料范围中的合规只读历史。重新附加材料后产生新的范围，旧的无材料历史不会成为当前材料证据。

### 本地意图路由

新增纯函数：

```js
detectChatIntent(question, {
  route,
  materialMode,
  hasTopic,
  hasTracking,
  capabilities,
})
```

返回：

```js
{
  capability: 'ask' | 'topic-ask' | 'disagreement' | 'comparison' |
    'unresolved' | 'new-replies' | 'draft' | 'tracking' |
    'site-action' | 'research',
  confidence: 'high' | 'medium' | 'low',
  source: 'local',
  reason: 'topic-analysis' | 'research' | 'tracking' |
    'explicit-action' | 'fallback'
}
```

路由规则按以下优先级执行：

1. 明确的站内写动词和目标进入 `site-action`，但仍必须经过现有计划校验和二次确认。
2. 明确的检索、追踪、帖子分析和结构化分析词进入对应只读能力，并检查当前材料是否满足要求。
3. 材料缺失或页面范围不支持目标能力时，显示本地提示并降级为普通只读问答；不自动读取新的材料。
4. 模糊问题默认进入 `ask`，不让模型的历史内容授权新的能力。

能力解析结果写入当前 turn 的可选字段，方便消息态显示实际处理方式；它不改变历史中旧写操作的状态，也不授予新的写权限。

## 侧栏 API 边界

工作台不能直接查询或修改氢壳的 tab DOM。基座 UI 增加受控的 `shellAsideSelect(id)` 接口：

- 只接受 `site` 或当前已注册的侧栏视图 ID。
- 由氢壳监听并调用内部 `asideSetActive`。
- 视图不存在时安全回退到 `site`。
- 工作台关闭按钮只调用该接口，不处理皮肤节点、宽度或 body padding。

相关 API 变化由 `src/ui.js`、`src/core.js` 和 `plugins/skin.user.js` 共同完成，并加入基座和皮肤测试。

## 兼容和迁移

- 对话存储继续使用现有 `version: 1`；`materialMode`、`intent` 和新范围字段均为可选字段。
- 旧 turn 缺少 `materialMode` 时按 `attached` 读取，旧的 `contextKind` 和引用仍按原规则渲染。
- 旧的隐藏 `data-ai-chat-context`、`data-ai-chat-mode` 和 `data-ai-chat-mode-options` 保留一个版本周期，仅用于兼容既有测试和内部调用，不回到可见界面。
- 旧缓存通过新增材料模式和意图路由版本自然失效，不做破坏性清理。
- 工作台版本从 `0.7.1` 升至 `0.8.0`。若新增 `shellAsideSelect` 公共 API，基座同步升一个补丁版本；构建脚本自动同步 Hydrogen、Oxygen 和 LTS 产物版本。
- 不迁移正在进行的请求。刷新、关闭和路由切换继续把在途请求标记为可重试或结果未知，不能自动重放写操作。

## 测试和验收

### 纯函数和基座测试

- 意图路由：普通问题、帖子分析、比较/分歧、检索、追踪、明确写请求、模糊问题、材料缺失和无效能力。
- 材料范围：附加/取消会改变请求指纹和范围；无材料请求不包含帖子正文和引用账本。
- 历史安全：历史里的写操作、提示注入文本和旧引用不能改变当前能力或授权。
- 侧栏 API：只允许已注册视图，关闭工作台回到 `site`，未知 ID 安全回退。

### 工作台 DOM 测试

- 空会话只显示欢迎态、星标和建议问题。
- 首轮发送后欢迎态消失，消息态和固定 composer 出现。
- 可见 DOM 不包含 `@ 当前页面`、`/ 提问` 或 Smart 能力选择器。
- 更多菜单、新建/切换/清空、AI 设置、关闭回站点均可用。
- 材料条取消后请求不携带当前页面材料，回答不产生引用；重新附加后引用链恢复。
- 停止、重试、连续追问、引用复核、站内操作确认和结果检查继续通过现有断言。

### 真实浏览器验收

本地模拟模型和 fixture 页面覆盖：

1. 360–384px 深色侧栏、顶部按钮、欢迎中心位置和底部蓝色渐变。
2. composer 始终贴在侧栏底部，更多菜单、材料菜单不覆盖输入卡。
3. 建议问题填充输入框；自然语言自动进入正确能力；模糊问题安全降级。
4. 点击材料 `×` 后请求不读当前页面且没有引用；重新附加后请求恢复引用。
5. 关闭、切换对话、停止、重试、网络中断和写操作确认没有回归。

## 交付拆分

### M15.1：Gemini 式深色外壳

只替换工作台 DOM 结构和样式，完成欢迎态、消息态、顶部菜单、底部 composer、材料条、模型标签和侧栏关闭 API。业务请求仍使用现有能力选择，确保外壳先稳定。

### M15.2：自然语言路由与材料控制

加入 `detectChatIntent`、材料附加/取消、无材料范围和缓存隔离。移除可见 Smart 选择器，保留隐藏兼容层和低频能力兜底入口。

### M15.3：兼容迁移与完整验收

覆盖旧历史、旧缓存、停止/重试、引用复核、站内写操作和窄屏入口；同步版本、README、Hydrogen/Oxygen/LTS 产物，执行完整回归和真实浏览器验收。

现有路线中“模型端点能力与诊断”顺延到 M16，“对话导出与可移植性”顺延到 M17，避免和本轮大规模 UI 迁移并行扩大风险。

## 完成标准

- 侧栏视觉和布局符合参考图的欢迎态与输入卡层级。
- 任何菜单都不会与输入卡重叠，动态输入高度和窗口宽度下仍可用。
- 自然语言路由只影响只读能力选择；写操作仍由现有本地校验和二次确认保护。
- 取消材料的请求不读取当前页面、不生成引用，重新附加后恢复正常证据链。
- 旧历史可读，M12–M14 回归通过，构建和发行产物校验通过。
