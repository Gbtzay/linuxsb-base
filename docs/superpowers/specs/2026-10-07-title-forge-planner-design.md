# UR 合成规划器设计

日期：2026-10-07
范围：新增独立 Oxygen 插件 `plugins/title-forge-planner.user.js`，根据 UR 合成表、称号行情、抽取概率、当前积分和称号库存，计算合成表内任意 UR 的可行性与最低成本路径。
非目标：购买称号、抽取称号、提交合成、AI 推理、修改基座请求协议、修改 LTS、修改 iOS 27 / legacy 壳的通用导航。

## 1. 目标

用户打开「UR 合成规划」面板后，插件自动读取当前可用数据，并同时展示两种库存假设：

1. 不计入当前库存：假设所有材料都需要重新取得。
2. 计入当前库存：从 `/gacha_profile` 读取已有称号，并只计算缺少的材料。

每种库存假设都要同时计算三类方案：

- 市场最低立即成本：按当前挂单的实际价格和数量逐单购买；
- 市场中位价估算：按称号行情的中位价估算；
- 抽取期望成本：按 `/gacha` 页面明确给出的抽取消耗和概率计算期望积分。

如果有任意 UR 的有效方案不超过当前积分，指出积分消耗最低的 UR 和具体路径；如果全部不足，指出有效方案中缺少的最少积分。抽取方案必须明确标为期望值，不承诺实际抽取结果一定不超过该成本。

## 2. 总体架构

新增 `title-forge-planner` 插件，声明依赖：

- 基座 `^0.2.2`；
- `title-quotes` 的市场数据提供能力，版本从本功能开始升至 `^1.0.19`。

`title-quotes` 增加只读 RPC `title-quotes:market-data`。RPC 返回最近一次成功采集轮的：

```js
{
  fetchedAt: 0,
  listings: [{ key, price, qty }],
  titles: { [key]: { rarity, lo, hi, mid, n } }
}
```

`listing_id` 不对规划器公开；`key` 使用现有 `name@rarity` 约定。为支持跨标签页使用，成功采集的单个挂单摘要写入 `title-quotes` 自己的存储命名空间，RPC 从该快照返回，而不是只依赖当前标签页内存。

规划器在面板首次打开或用户点击「刷新数据」时按需读取：

- `/gacha_recipes`：合成配方；
- `/gacha`：抽取消耗、抽取池和概率；
- `/gacha_profile`：当前称号库存；
- `api.me.points`：当前积分；
- `title-quotes:market-data`：最低挂单、中位价和挂单数量。

规划器只申请读取、存储、界面和事件能力，不申请写入或跨域能力。所有请求都使用 `api.net.doc`，不提交购买、抽取或合成请求。

新插件加入 Oxygen `ORDER` 并放在 `title-quotes` 之后，不加入 `ORDER_LTS`。第一版只注册基座面板页，不修改 `skin.user.js` 的旧三栏或 iOS 27 入口，避免与当前双 UI 模式改动耦合。

## 3. 规范化数据模型

解析器把页面转换为以下结构。页面字段缺失时返回缺失状态，不以默认零值填充。

```js
{
  recipes: [{
    id,
    target: { key, name, rarity: 'UR' },
    inputs: [{ key, name, rarity, qty }],
    fee
  }],
  market: {
    fetchedAt,
    listings: [{ key, price, qty }],
    titles: { [key]: { rarity, lo, mid, n } }
  },
  gachaPools: [{
    id,
    label,
    drawCost,
    outcomes: [{ key, probability }]
  }],
  inventory: { [key]: qty },
  points: number | null
}
```

### 3.1 配方

- 只收录目标稀有度为 UR 的最终结果，但保留配方中出现的下级配方引用。
- 同一 UR 的多条配方全部保留，计算器逐条比较。
- 配方费用必须是明确解析出的积分数；无法解析费用的配方标为不完整。
- 配方键以称号名和稀有度组合，避免同名不同稀有度混淆。

### 3.2 抽取概率

- 页面直接提供称号级概率时直接使用。
- 只有稀有度概率时，仅当页面同时明确给出该稀有度的等概率称号池，才展开为称号级概率。
- 未明确的概率、无法确认的奖池成员和未标明的保底规则不自行推断。
- 抽取池至少需要明确抽取积分和可用于当前材料的结果概率；否则该池不参与计算。

### 3.3 当前库存

- `/gacha_profile` 解析为 `name@rarity -> quantity`。
- 不计库存模式把所有数量视为零。
- 计入库存模式按每个候选 UR 独立计算，库存不会在不同 UR 之间共享或被前一个结果消耗。
- 无法确认库存时，不计库存模式仍可运行；计入库存模式显示数据不可用。

## 4. 成本计算

### 4.1 材料缺口和多级配方

对每个 UR 配方计算材料需求，先扣除当前库存，再处理缺口。若材料本身存在下级配方，计算器同时考虑直接取得和按下级配方合成的候选路线，并使用有环检测拒绝循环路径。路线搜索遇到缺少价格、概率或配方费用时，只丢弃该候选，不影响其它完整候选。

每个候选路线都会包含可展示的步骤树：目标 UR、配方费用、每种材料需求、库存抵扣、市场购买或抽取动作，以及中间合成步骤。

### 4.2 市场最低立即成本

按当前 `listings` 的单价升序逐单取货：

1. 对每种缺少的材料筛选对应挂单；
2. 先使用价格最低的挂单，按 `qty` 扣减；
3. 继续使用下一条挂单直到材料满足需求；
4. 所有材料成本加上各级配方费用。

如果当前挂单总量小于需求量，市场最低方案标为「当前挂单不足」，不得把不足部分按零成本或最低单价补齐。

### 4.3 市场中位价估算

使用最新行情中每个称号的 `mid` 乘以缺少数量，再加上各级配方费用。该方案不模拟具体挂单数量，界面明确标注「中位价估算」。如果没有该称号的中位价，方案不可用。

### 4.4 抽取期望成本

对一个候选抽取池，把“尚缺少的材料数量”作为有限状态。每次抽取会：

- 按概率得到一个结果；
- 若结果仍是需要的材料且数量未满足，则减少一个缺口；
- 其它结果或已满足材料保持当前状态。

从缺口较小的状态反向计算期望成本。对于每个可选抽取动作，使用：

```text
候选期望成本 =
（本次抽取消耗 + 所有有进展下一状态的概率加权期望成本）
÷（1 - 无进展概率）
```

选择期望成本最低的有效抽取动作，因此能处理重复抽取和一个抽取池同时覆盖多种材料的情况。概率数据不完整时，不把未知部分当作“无进展概率”，而是使该抽取池不可计算，避免用不完整分布制造虚假结果。

抽取路线显示期望抽取次数和期望积分，并使用「期望值，不保证实际结果」提示。

### 4.5 可行性

每个方案统一返回：

```js
{
  cost,
  currentPoints,
  canSynthesize: currentPoints != null && cost <= currentPoints,
  remaining: currentPoints == null ? null : Math.max(0, currentPoints - cost),
  shortfall: currentPoints == null ? null : Math.max(0, cost - currentPoints)
}
```

每个 UR 保留三类方案和其中的最低有效方案。全局摘要按以下顺序选择：

1. 积分足够的方案优先；
2. 总积分成本最低；
3. UR 名称稳定排序。

如果没有积分足够的方案，则选择缺口最小的有效方案，并分别展示市场最低、市场中位和抽取期望路线的缺口。若所有路线都缺少必要数据，摘要显示无法判断，而不是显示“还差 0 积分”。

## 5. 面板界面

新增面板页名称为「UR 合成规划」。

### 5.1 顶部状态

显示：

- 当前积分；
- 最后计算时间；
- 「刷新数据」按钮；
- 合成表、抽取概率、我的库存、称号行情四个数据源的状态和更新时间。

### 5.2 结果区

结果分为两个固定区块：

- 「不计库存」；
- 「计入当前库存」。

每个区块先显示最优摘要：当前是否存在积分足够的 UR、目标名称、路线类型、预计消耗和剩余积分；全部不足时显示缺口最小的目标和缺口积分。

下面按 UR 显示可展开行。每行包含：

- UR 名称和配方；
- 三类路线的成本与状态；
- 当前积分下的剩余或缺口；
- 展开后的材料清单、库存抵扣、挂单明细或抽取期望次数；
- 数据来源时间和过期提示。

排序时积分足够的方案置顶，再按有效成本升序，最后按 UR 名称排序。用户可以看到所有已解析的 UR，不只看到全局最优项。

## 6. 刷新和异常处理

- 打开面板时执行一次按需刷新；之后只由用户手动刷新，不新增后台轮询。
- 刷新时每个来源独立记录成功、失败和更新时间。
- 某来源刷新失败时保留上次成功的规范化数据，并显示“上次成功时间 / 本次失败”；使用旧数据的结果统一显示“数据可能已过期”。
- `/gacha_recipes` 失败或没有可解析 UR 时，不生成任何 UR 结论。
- `/gacha` 失败时，市场路线继续显示，抽取路线标为数据不足。
- `/gacha_profile` 失败时，不计库存继续显示，计入库存标为无法确认。
- 行情 RPC 无数据时，市场路线标为不可用；抽取路线仍可计算。
- 页面返回登录页、Cloudflare 挑战页或无法识别的 HTML 时，来源状态分别显示需要登录、挑战未完成或页面格式无法识别；这些页面不当作空配方、零概率或零库存。
- 当前积分无法读取时，仍显示可计算的成本，但不判断是否能够合成。
- 所有异常只影响本插件，不阻塞行情、皮肤或其它插件。

## 9. 验收标准

1. 在完整夹具数据下，面板同时显示不计库存和计入库存两组结果。
2. 市场最低方案按真实挂单数量累加，不把最低单价错误套用到全部材料。
3. 市场中位方案与行情快照的 `mid` 一致，并标记为估算。
4. 抽取方案使用页面明确概率，能处理重复抽取，并显示期望值提示。
5. 当前积分足够时，明确指出可完成的最低成本 UR 和路线。
6. 当前积分不足时，明确指出缺口最小的 UR 和缺少积分。
7. 缺少数据时显示不可判断或路线不可用，不把缺失值当作零。
8. 测试、套件构建、dist 校验和差异检查全部通过。
9. 功能不发送任何购买、抽取、合成或其它站内写请求。
