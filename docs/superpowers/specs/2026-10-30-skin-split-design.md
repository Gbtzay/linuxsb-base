# skin 分步拆分：第一步

将画布状态纯函数变成打包与测试共同使用的唯一源码，并建立可复验的分文件生成链路。用户界面、存储格式、插件 ID、权限和路由行为保持当前契约。

## 边界

- `plugins/skin/canvas-state.js`：状态版本、默认外观/浮层、深复制/合并、宽度分类、站点键、矩形约束与旧配置迁移；原生 ES 模块，不访问 DOM 或存储。
- `plugins/skin/skin.template.js`：userscript 头、manifest、挑战页检测、AI markup、setup 与尚未拆分的界面逻辑；仅在明确标记处注入状态模块。
- `plugins/skin.user.js`：生成的可安装脚本，保留现有路径和注册形式，标注编辑入口。其他插件不改变源码模式。
- `scripts/build-skin.mjs`：按显式文件和唯一标记生成；去掉状态模块声明的 `export` 前缀，保留函数名、代码文本和 AI 标记，不改写运行时闭包。拒绝 BOM/CRLF、缺失或重复注入标记、各文件内不配对的 AI 标记和语法错误。
- 构建读取组合源码，生成独立脚本后再执行已有的 dev/release AI 裁剪。校验为只读：生成文件或套件滞后必须失败。测试入口不能悄悄运行旧的生成文件。
- 现有 `src/shell/canvas.js` 和 `src/shell-canvas.js` 作为兼容转出口，纯函数实现仅保留一份；它们未被 Hydrogen 运行时引用，本次不改变基座 API 或版本。
- 删除 `plugins/skin/` 中原先全部章节参考副本，所有尚未拆分的实现已完整保存在模板里。Git 历史仍可追溯旧文件。

## 验收

1. 修改纯函数源，真实套件构建的运行结果随之改变，即使旧 `skin.user.js` 尚未生成。
2. 修改模板或模块后，`verify:skin` / 产物校验拒绝过期生成文件；校验不写磁盘。测试启动前执行该检查。
3. dev 的默认浮层包含 AI，release/LTS 排除 AI 默认值与所有既有 AI 专用入口。
4. 独立脚本继续注册一次 skin；套件成员数不变，版本元数据一致。
5. 对提取前后保留的正文与纯函数代码进行归一比较，保存本轮证据；双界面阅读验收、完整 Node 回归与浏览器冒烟通过。

后续候选：样式生成函数 → 媒体资源生命周期 → 插件入口/导航 → DOM 接管与软跳。每一步以清楚的输入、清理责任和专项验收为界，本轮仅完成状态模块与生成链路。
