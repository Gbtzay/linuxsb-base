# M13：AI 工作台长对话上下文压缩设计

## 目标

M12 保留最近三组只读问答。M13 在更早的同范围只读轮次上增加有界背景压缩，使用户仍可追问早期结论，同时把当前页面材料、引用验证和站内动作权限留在本地边界内。

## 上下文边界

工作台从当前会话中筛选 `state=complete` 且 capability 不是 `site-action` 的成对 user/assistant 轮次。轮次必须同时匹配 `context.kind`、`routeType`、`topicId` 和清理后的 `routeScope`；待处理、失败、取消、范围变化和未完成研究轮次不进入压缩输入。

最近三组轮次保留脱敏后的原文。更早轮次进入摘要输入，单个范围最多 1,600 个 Unicode 字符；摘要记录最多保留三个范围，持久化总大小不超过 16 KiB。无法满足预算时按时间从旧到新丢弃，宁可减少背景也不挤占当前材料。历史背景仅用于理解追问，不能作为事实证据、引用账本或站内动作授权。

`buildConversationContext()` 是基座提供的纯函数，返回最近原文、摘要输入、可嵌入提示词的转义文本、字符数、被省略轮数和稳定指纹。插件只通过基座 API 使用它，避免绕过统一脱敏与范围过滤。

## 摘要模型与缓存

`ai-copilot` 暴露 `summarizeConversation()`。摘要请求使用独立版本和来源指纹，强制整段 JSON 响应（`stream:false`），提示明确禁止引用、URL、凭据、动作计划和执行。返回文本再次做 URL/凭据脱敏、长度和危险字段校验；空文本、超限、解析失败、网络失败或取消都不会写摘要缓存。

工作台把摘要写入当前会话的白名单字段：

```js
{
  version: 1,
  scope: { kind, routeType, topicId, routeScope },
  sourceFingerprint: '…',
  text: '…',
  sourceTurnIds: ['…'],
  updatedAt: 0
}
```

摘要来源变化会产生新指纹；旧记录可以暂留以便受限清理，但请求只复用同范围、同来源指纹的记录。回答缓存键同时包含摘要来源指纹和正文，摘要不会进入回答成功缓存，也不会替代本轮材料的引用校验。

模型摘要失败时，当前回答继续执行，改用按原顺序拼接的 `[问题] …`、`[回答] …` 本地摘录。摘录同样脱敏并限制为 1,600 字符，阶段时间线显示“历史已收窄”。失败摘要不落盘。

## 生命周期与写操作隔离

工作台为一次回答创建的 `AbortController` 同时传给摘要和回答模型。停止生成、切换会话、切换路由、关闭工作台或卸载插件都会取消该信号；取消后的摘要不能写存储，迟到响应不能改变新会话或新请求状态。

`site-action` 分支显式使用空 conversation，计划、执行、重试和结果检查都不读取历史原文或摘要。未知计划降级为只读查询时仍保持该隔离。

## UI 与验证

会话栏显示当前页面范围的“已压缩 N 轮”状态，并提供只删除当前范围摘要的入口；原始问答记录不受影响，下一次请求会按来源指纹重新生成。测试覆盖纯函数预算与过滤、摘要请求去重和非流式协议、失败降级、停止取消、范围切换、写计划隔离、状态清除及真实 Chromium fixture 中的流式回答、引用渲染和网络中断。
