# AI 工作台查询当前页列表设计

日期：2026-10-01
状态：设计已由用户确认，等待文档审阅

## 背景

AI 工作台的自然语言查询目前读取本地问题追踪项和帖子页楼层。用户选择扩大到“当前页可见列表”，并确认首版只读取当前已经渲染的列表，不翻页、不额外抓取主题正文。

站点基座已提供 `api.parse.list(document)`，用于解析首页、版块、精华和足迹等主题列表；用户页通过 `api.parse.user(document).items` 提供当前列表条目。站内搜索结果通常由 `/index.php` 呈现，也可通过相同列表解析器读取。数据采集不需要新网络请求。

## 目标

- 让用户可以用自然语言询问当前页面主题列表中的帖子。
- 保持两阶段只读查询：模型先选择范围，本地解析和筛选，回答阶段只使用本地结果。
- 让每条列表结果使用本地验证的主题链接作为引用。
- 不增加翻页、后台抓取或站点写入行为。

## 范围

### 支持的数据

- 首页、版块、搜索结果、精华和足迹页中当前已渲染的主题列表。
- 用户页中当前选项卡能由 `api.parse.user(document).items` 解析出的主题条目。
- 帖子页继续使用现有的帖子楼层上下文和追踪项查询。

列表条目必须有有效的正整数主题 ID。读取列表时使用当前 DOM 的解析结果，避免复用同路由的陈旧快照。虚拟滚动或无限滚动已经加载到 DOM 的条目可以包含在结果中；本次查询不会主动加载更多条目。

### 不包含的数据

- 未加载的分页或其他版块、主题。
- 当前列表主题的正文楼层。
- 私信、通知或未由主题列表解析器支持的页面内容。
- 站点写入操作。

## 交互和数据流

1. 本地上下文收集当前页面类型、当前列表是否可用及条目数量。第一阶段不发送列表标题或作者等条目数据。
2. 查询计划升级为版本 2，增加必需布尔字段 `includeCurrentList`。模型根据用户请求决定是否读取当前列表；本地验证会在页面不支持或列表为空时将该字段收窄为 `false`。活动追踪专用范围仍不能读取当前列表。
3. 本地执行器仅在计划选择当前列表时读取条目；按现有主题 ID 和关键词条件筛选，最多保留 40 条，并受既有 `CONSOLE_MAX_CHARS` 总字符预算约束。
4. 发送给回答模型的列表字段仅包括主题 ID、标题、作者名称、版块名称、回复数、最后活跃时间和置顶标记。用户 ID、原始 HTML 和原始 URL 不进入模型请求。
5. 回答引用采用 `[[topic:<id>]]`。本地只把引用映射到本次结果中的主题 ID，并生成站内主题链接；未知 ID 显示为未验证引用，不采信模型提供的链接。
6. 列表结果参与答案缓存指纹，使列表发生变化时不会复用旧列表答案。查询计划缓存指纹包含计划版本和列表可用状态，避免继续使用旧版计划。

## 失败和边界处理

- 页面没有受支持的主题列表时，不发起额外站点请求；查询继续使用现有追踪项或当前帖子数据。
- 用户要求查询当前列表但当前列表为空时，结果注明列表为空；若追踪项等其他来源有结果，仍使用这些来源回答。所有来源都为空时，跳过回答模型并给出清楚提示。
- 条目超过 40 条或字符预算时截断结果，并在本地结果元数据中标出截断状态。
- 只有当前页解析出的主题 ID 可以生成引用；模型不能通过提供任意 URL 创建链接。

## 验收标准

- 首页、版块、搜索结果、精华、足迹和用户主题列表都能从当前渲染内容中解析条目。
- 用户询问当前列表时能选中该数据源；没有询问列表时，计划可以不带列表数据。
- 计划缓存版本升级后旧计划不会遗漏新字段。
- 结果受 40 条和字符预算双重限制，且不会触发翻页或主题正文请求。
- 有效主题引用生成本地站内链接；未知主题引用不生成链接。
- 没有解析器支持的列表时不会抛错或调用额外网络请求。
- AI 副驾测试、套件测试、全量测试、构建和 `verify:dist` 全部通过。
